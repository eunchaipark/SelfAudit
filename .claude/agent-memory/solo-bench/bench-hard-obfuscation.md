T24(2026-11-24, 작업 쌍 A 한 세션 쪽)에서 정한 것과 걸린 것.

- 난독화는 파일 전체에 건다: 모든 글·이름 접근(`a.b`)·객체 열쇠를 배열로 옮기고 글자 코드(`\x7a`)로 적는다.
  **Why:** 일부 글만 옮기면 '배열에 있는 글 = 숨긴 것'이라는 겉모양 단서가 생긴다(공정성). **How to apply:** 정답·미끼 모두 같은 배열을 거치므로 미끼를 따로 숨길 필요가 없다. 난독화 파일 본문에 따옴표가 하나도 없어야 한다(시험이 본다).
- 소스맵은 난독화하지 않은 파일에만 붙인다. 맵의 `sourcesContent`는 변환 전 원본이라 난독화 파일에 붙이면 숨긴 값이 맵에 글 그대로 나온다. `sourcemap_only`는 압축이 지우는 주석에 값을 둔다.
- 원본 꼴 제약(멈춤): 템플릿 글, 정적 `import … from`, 글 안 줄바꿈, 모르는 이스케이프. `{` 뒤 이름 + `:`는 열쇠로 보므로 블록 안 라벨·`=> { a: 1 }`을 쓰지 않는다. 줄 첫머리 `.then` 같은 줄바꿈 체인은 쓰지 않는다.
- 닻: 긴 값은 `charcode:16`(앞 16자의 글자 코드), 짧은 글은 통째 글자 코드를 `answers.in.json`에 글로 적는다(`\\x..` — JSON에서 백슬래시 두 번). 원본을 고치면 해시 이름이 바뀌어 맵 이름 닻(`receipt-<해시>.js.map`)도 고친다 — `answers` 명령이 '문제 1곳'으로 알려 준다.
- 정답지 미끼에는 `decoded_anchor` 칸이 없어서, 난독화 미끼를 풀어낸 값으로만 가리킨 결과는 '미끼 헛짚음'으로 이름 붙지 않는다(계약 한계, 보고서 T24 요청에 적음).
- 문법 검사는 PATH의 `node --check`(실행 없이 읽기만)로 시험한다. node가 없으면 건너뛴다.
- 이 worktree에서 heredoc·`sed -i`·`&&` 섞은 명령은 막힐 때가 있다. scratchpad에 파이썬 고침 스크립트를 Write로 쓰고 `python -I <스크립트> <대상>`으로 돌린다. 원본 고침 뒤 `answers <id>` 하나로 번들·정답지를 다시 만든다.
- 쓴 접두어: `drovik_`(hard-1), `nuvor_`·`oskel_`(hard-2). 앞서 쓴 접두어 목록은 lane-bench 메모 `bench-build-traps.md`에 있다.
