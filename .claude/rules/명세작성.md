# 명세 작성 (docs 파일을 열면 자동으로 읽힌다)

전체 기준은 `docs/문서규칙.md`. 명세는 문서 역할만 고친다(규칙 문서 `코드규칙`·`보안규칙`·`00_지도`는 설계).

- 기능 절 제목은 ID로 시작: `### F-A01 순자산 (FR-101)`. 그 절만 읽어도 만들 수 있게.
- 기능마다 입력 · 처리 규칙(번호) · 출력 · 예외 · 화면, 그리고 **숫자로 된 예시**(평범한 경우 + 경계값). 예시가 테스트가 된다.
- 계산 예시는 직접 계산해서 확인한다. 숫자는 가상임을 밝힌다.
- 새 번호는 `python ops/scripts/impact.py --next <접두어>`. 다시 매기지 않는다. 지운 기능은 보류 목록으로.
- 정하지 못한 것은 `미결:` + 결정기록. 단정하지 않는다("후보", "가능 요인", "가정에 따른 계산").
- 변경 요청으로 바뀐 절 끝에 `(CR-<번호>)`. 변경 이력 한 줄, 버전은 사용자가 원할 때만(그 밖에는 "(버전 유지)").
- 고치기 전에 영향부터: `python ops/scripts/impact.py <ID>`. 앞 문서부터 고친다.
