# 서버 코드 (서버 파일을 열면 자동으로 읽힌다)

전체 기준은 `docs/코드규칙.md` 4장.

| 계층 | 할 일 | 하지 않을 일 |
|---|---|---|
| api | 입력 검증, 서비스 호출, 응답 스키마 | 계산, DB 직접 접근, 외부 호출 |
| service | 흐름과 트랜잭션 경계 | 계산 규칙 직접 구현 |
| engine | 순수 계산, 불변 입력·출력 | DB, 네트워크, `now()`, 전역 난수, 값 로그 |
| client | 외부 호출, 형식 검사, 내부 모델로 변환 | 비즈니스 판단 |
| db | 모델, 저장소 | 비즈니스 판단 |

- 쿼리는 ORM 또는 바인드 파라미터로만.
- **마이그레이션은 만들지 않는다.** 필요하면 요청한다(한 번에 한 태스크만 만든다).
- 오류 응답은 한 가지 형식: `{"code": "…", "message": "…"}`. 스택·SQL·개인 값을 넣지 않는다.
- 외부 호출은 `clients/`에서만, 시간 제한 필수, 응답은 검증한 뒤 쓴다.
- 도메인 오류는 공통 오류 클래스를 상속한다. 예외를 조용히 삼키지 않는다.
- 로그에는 ID와 출처 이름만.
- **실험 도구(`bench/`)**: 위 계층 표 대신 순수 계산(검증·지문·짝짓기·지표)과 바깥과 닿는 일(프로세스 실행·파일 읽기·쓰기)을 다른 함수로 나눈다. 계약 검증·번들 지문·경로 정규화는 `bench/common`의 것만 쓰고 다시 만들지 않는다(지도 '공통 함수'). DB·마이그레이션·오류 응답 줄은 해당 없음.
