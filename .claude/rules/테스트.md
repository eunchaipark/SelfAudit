# 테스트 (테스트 파일을 열면 자동으로 읽힌다)

- 이름: `test_<기능ID>_<상황>` (예: `test_F_A01_예시합계_38420000`). 기능 ID가 명세 → 테스트 → 보고서를 잇는 고리다.
- 기능명세의 예시(입력 → 출력)를 숫자 그대로 옮긴다. 예시가 없는 계산은 경계값 1~2개만.
- 외부 접속은 막는다. 외부 응답은 키·개인 값을 지운 고정 파일(fixtures)로 쓴다.
- 실제 개인 데이터는 넣지 않는다. 합성 데이터만.
- `bench/`: 대상 번들은 시험 안에서 `make_bundle` 픽스처(`bench/tests/conftest.py`)로 만든다. 실제 `claude.exe`·REA는 부르지 않고 가짜 실행 파일로 시험한다(실험구조 3.9). 공통 시험 이름은 `test_common_<상황>`.
- 코드를 쓰는 동안에는 지금 만드는 기능의 테스트만 돌린다. 끝에 `python ops/scripts/check.py` 전체를 한 번.
- **실패를 없애려고 기대값을 바꾸지 않는다.** 기대값이 틀려 보이면 멈추고 명세 문제로 보고한다.
- 명세가 바뀌어 기대값을 바꿔야 할 때는, 태스크 머리줄에 `변경: CR-n`이 있고 testStrategy에 `기대값 변경: <테스트 이름>`으로 적힌 테스트만 바꾼다. 커밋 메시지에 CR 번호를 적는다.
