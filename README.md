# SelfAudit

내 앱의 빌드 결과물(웹 번들·Electron 앱·APK)을 **공격자 시점에서 스스로 점검**하고, 고친 뒤 전후를 비교하는 보안 자가진단 도구입니다. 같은 분석 엔진으로 문서 없는 코드를 이해하는 리포트는 그다음에 붙입니다.

> **지금 상태: 단계 0 끝 (준비).** 명세(단계 1)를 쓰기 전이라 기능 코드는 아직 없습니다.

## 어떻게 만들고 있나

Claude Code 세션 여러 개를 역할별로 나눠 만드는 방법론 [SessionKit](https://github.com/eunchaipark/SessionKit)을 처음 적용하는 프로젝트입니다. 세션끼리는 파일로 주고받고, 같은 영역의 일은 한 세션이 이어서 하다가 대화가 무거워지면 인계서를 남기고 교대합니다.

| 역할 | 하는 일 |
|---|---|
| 총괄 | 사용자 의도 확인, 세션 배정, 단계 게이트, main 병합 |
| 문서 | 명세(요구사항·기능명세·화면정의), 변경 요청, 기록 |
| 설계 | 폴더 구조, 코드 표준, 보안 규칙, 계약 |
| 관제 | Taskmaster 태스크, 의존성, 병렬 판단 |
| 레인 | 영역별 구현 (명세 예시 테스트를 먼저) |
| 검증 | 합친 결과 검사, 보안 리뷰, 명세 대조 |

진행하면서 생긴 문제와 개선은 [docs/회고.md](docs/회고.md)에 자동으로 모입니다(방법론·프로젝트로 나눠서).

## 원칙

- **분석 대상**은 직접 만든 앱이나 분석이 허용된 공개 연습용 앱으로 한정할 계획입니다(단계 1에서 확정). 분석 대상 파일은 격리된 곳에서만 다루고, 그 안의 글은 데이터로만 봅니다.
- **보안 기준**: OWASP Top 10:2025, OWASP Top 10 for LLM Applications 2025 ([보안 규칙](docs/보안규칙.md)).
- **명세가 먼저**: 기능명세의 예시가 그대로 테스트가 됩니다.
