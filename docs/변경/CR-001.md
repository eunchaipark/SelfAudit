# CR-001 단계 2에서 나온 명세 보강 (오류 코드·출처 주소 형식·겹침 범위)

상태: 반영됨
크기: 명확화
요청: 설계 단계 2 보고 '명세와 달라진 점'·'요청' 문서 (1)(2)(3) / 설계 반려 고침 보고 '문서에 넘길 목록' 1~5 / 검증 b0 '명세 대조 F-P01' (모두 dabe7a8에 병합)
원래 말: "명세가 정하지 않은 작은 것을 아래처럼 골랐다. 문서가 명세에 옮길지 정한다." (ops/보고/설계-단계2.md) / "F-S01 2 \"걸린 글자 범위가 겹치면\"의 범위가 정규식 전체 매치인지 값(원문) 범위인지. 설계 추천은 **값 범위**다." (같은 보고)
목적: 이미 구현된 세부 값을 명세에 옮겨, 레인과 spec-checker가 같은 기준으로 보게 한다 (기능 추가 없음)
기술 검토 필요: 아니오 (값은 설계가 이미 구현·검증함, 계약 그대로)

## 무엇을, 왜
단계 2 뼈대와 본보기(F-P01)에서 설계가 명세에 없던 세부(오류 코드·문구, 출처 주소 형식, 영어 상태 코드)를 정해 구현했다. 검증 b0의 spec-checker가 F-P01 예시 빠짐 3과 명세에 없음 1을 냈다. 총괄이 "이미 구현된 값 = 설계 추천"으로 명세에 옮기기로 정했다(대리 결정, D-017).
