## 무엇을, 왜
T18 보안 검토가 명세 문장 그대로 만든 구현에서 원문이 남는 꼴을 찾았다. 셋 모두 명세가 그렇게 쓰여 있어서 레인이 혼자 고칠 수 없다. (a) URLCRED 자기 조각은 '걸린 곳 앞과 뒤 따로'라 사용자 이름이 남고, (b) ㉠의 구분자가 `:` `=` 하나뿐이고 따옴표 안 `\"`를 닫는 따옴표로 보며, (c) `.map` 이름 접두는 제어 문자만 바꾸고 가리지 않는다. (d)(e)는 다른 검증에서 넘어온 같은 크기의 명확화라 함께 둔다.

## 항목별 선택지 (★ = 추천)

**(a) 주소 속 사용자 이름 — URLCRED 걸림 자신의 근거 조각 (1절 '근거 조각' ㉡) — 명확화, 총괄 대리 가능**

상황: `"https://admin:pw1234567@internal.myapp.kr"`의 S01-URLCRED 발견. 걸린 곳은 비밀번호(`pw1234567`)뿐이라 ②가 `****`로 바꾼다. ㉡은 앞(`"https://admin:`)과 뒤(`@internal…`)에 따로 하므로 `@`를 못 보고, 조각이 `"https://admin:****@internal.myapp.kr"`이 된다. 같은 주소가 **다른** 발견(AWS 등)의 조각에 들면 ㉡이 `https://****@…`로 덮는다. 사용자가 D-029에서 정한 "근거 조각에서 URL `사용자:비밀번호@`를 `****@`로"가 자기 조각에서만 빠진 셈이다.
- 안 A ★: S01-URLCRED 걸림 자신의 근거 조각에서는 ㉠㉡③을 한 앞쪽 글 끝의 `사용자 이름:`(`http(s)://` 바로 뒤부터 걸린 곳 앞까지)을 지운다. 결과 `"https://****@internal.myapp.kr"` — 다른 발견의 조각에 보이는 모양과 같다. 걸린 곳 자체(`****`)는 바꾸지 않는다는 규칙은 그대로
- 안 B: ㉡을 앞·걸린 곳·뒤를 이은 글에 한 번 한다(모든 규칙). 같은 결과지만, 사용자 정보 자리에 다른 키가 걸린 경우(`https://AKIAIOSFODNN7EXAMPLE@x`) 걸린 곳의 가린 값(`AKIA****LE`)까지 `****`로 사라져 '걸린 곳은 바꾸지 않는다'가 깨진다
- 안 C: 그대로 두고 알려진 한계에 적는다(사용자 이름은 비밀값이 아니다)
- 추천 A: 사용자가 이미 정한 뜻(D-029)을 빠진 경우에 맞출 뿐이고 다른 규칙에 번지지 않는다. 승인된 예시 중 뒤집히는 것이 없다(184는 값·증거키만 적혀 있다)

**(b) 키워드 꼴 가리기를 흔한 JS 꼴로 넓히기 (1절 '근거 조각' ㉠)**

상황: ㉠은 "키워드가 든 식별자 + `["']?\s*[:=]\s*` 뒤의 값"을 가린다. 그래서 아래 꼴에서 짧은 비밀번호가 원문으로 남는다(모두 같은 줄의 AWS 키 발견의 근거 조각).
- `password==="hunter2"` → `=`만 구분자로 보고 `==`를 값으로 가려 `password=****"hunter2"`
- `pwd => "zz9"` → `>`를 값으로 가려 `pwd =**** "zz9"`
- `setItem("apiKey","sh0rt")` → `,`는 구분자가 아니라 그대로
- `password:"ab\"cdefg"` → `\"`를 닫는 따옴표로 보아 `password:"****"cdefg"`

(b-1) 이스케이프 — **명확화, 총괄 대리 가능**: "같은 따옴표 앞까지"가 `\"`를 닫는 따옴표로 보는지 명세가 말하지 않는다.
- 안 A ★: 따옴표 안에서 `\` 다음 한 글자는 값에 넣고 닫는 따옴표로 보지 않는다. `password:"ab\"cdefg"` → `password:"****"`, `secret:'it\'s'` → `secret:'****'`
- 안 B: 지금대로(`\"`에서 닫힘). `cdefg`가 남는다
- 추천 A: JS 문자열 규칙과 같고, 값 끝을 더 멀리 잡을 뿐이라 덜 가리는 일이 없다

(b-2) 구분자 넓히기 — **수정, 사용자 결정** (D-029에서 정한 ㉠의 꼴이 넓어진다):
- 안 A ★: 구분자를 `:` `=`에 더해 `==` `===` `!=` `!==` `=>`(긴 것부터)로 넓히고, 키가 따옴표로 닫힌 뒤 `,`와 따옴표 값이 오면(함수 인자·배열) 그 값도 가린다. `password==="hunter2"` → `password==="****"`, `pwd => "zz9"` → `pwd => "****"`, `setItem("apiKey","sh0rt")` → `setItem("apiKey","****")`
- 안 B: 비교·화살표(`==` `===` `!=` `!==` `=>`)만 넓히고 `,`는 넣지 않는다. `setItem("apiKey","sh0rt")`는 남는다(알려진 한계에 적음)
- 안 C: 넓히지 않고 네 꼴을 알려진 한계에 적는다. 화면 알림·Markdown 머리 문구("비밀값은 가려져 있습니다", "이 파일에는 비밀값 원문이 없습니다")를 "규칙에 걸린 비밀값은…"으로 약하게 고쳐야 사실이 된다
- 추천 A: 검토가 찾은 네 꼴이 모두 막힌다. 단점은 지나치게 가리는 것: `["password","email"]` → `["password","****"]`, `password===undefined` → `password===****`. 근거 조각에서만 생기고 발견·점수는 그대로라 받아들일 만하다. 따옴표 값이 아닌 인자(`setItem("apiKey", key)`)와 `>=`(`password >= 8`)는 가리지 않는다
- A여도 남는 것(알려진 한계에 더함): 괄호를 낀 화살표·getter(`getPassword:()=>"zz9"`, `get password(){return"zz9"}`), 키워드가 아닌 이름(`var pw='hunter2'`, 지금 한계 그대로)

**(c) `.map` 원본 파일 이름 가리기 (F-S01 9) — 수정, 사용자 결정** (CR-003 (c)에서 정한 "이름에는 ③을 하지 않음"에 가리기를 더한다)

상황: `.map`의 `sources`에 `https://deploy:s3cr3tTok@git.example.com/src/a.js`가 있으면 그 원본에서 나온 발견의 조각이 `[https://deploy:s3cr3tTok@git.example.com/src/a.js] password:"****"`로 시작해 비밀번호가 원문으로 남는다. 이름은 줄바꿈·제어 문자만 공백으로 바꾸고 S01 걸림·㉠㉡을 하지 않기 때문이다. 이름을 100자로 줄이는 것도 가리기 전이라 `x`×99 + `/AKIAIOSFODNN7EXAMPLE`(120자) → `[…` + `x`×79 + `/AKIAIOSFODNN7EXAMPLE] `로 키가 원문으로 남는다. U+202E(글자 차례를 뒤집는 방향 문자)·U+0085(C1)도 그대로 남아 화면에서 이름이 뒤집혀 보일 수 있다.
- 안 A ★: 이름 글 하나를 글 하나로 보고 ② (이름 안의 S01 걸림을 가린 값으로) → ㉠ → ㉡을 한 뒤 100자로 줄인다. ③은 지금처럼 하지 않는다(경로가 `/nod****`로 망가진다, CR-003). 이름의 걸림은 발견이 아니고 걸림 상한(11)에 세지 않는다. 바꾸는 글자는 줄바꿈과 (d)의 '보이지 않는 글자'(공백 하나로). 결과 `[https://****@git.example.com/src/a.js] password:"****"`
- 안 B: A + ③도 하되 이름에서는 `/`를 덩어리에서 뺀다(`[A-Za-z0-9+=_-]` 20자 이상). 형식 모를 긴 토큰도 막지만 긴 파일 이름(`react-dom.production.min.js`는 그대로, `SomeVeryLongComponentName.tsx` → `Some****.tsx`)이 망가진다
- 안 C: ㉡과 보이지 않는 글자만. 주소 속 비밀번호와 방향 문자는 막지만 이름 안의 AWS 키·`?access_token=…`은 남는다
- 추천 A: 검토가 든 꼴(주소 속 비밀번호, 이름 안의 형식 키, 방향 문자)을 다 막고 경로는 읽힌다. 남는 것: 형식이 없는 긴 토큰이 경로 조각에 박힌 경우(드묾, 알려진 한계에 적음). 비용은 이름마다 S01 규칙을 한 번 더 도는 것(걸림이 있는 항목의 이름만, 선형)

**(d) zip 실패 문구의 보이지 않는 글자 (F-I01 예외) — 명확화, 총괄 대리 가능**

상황: 실패 문구 `<항목>`은 U+0000~U+001F만 `\x0A`처럼 바꾼다. U+007F·C1(U+0080~U+009F)과 방향 문자(U+202A~U+202E, U+2066~U+2069)는 그대로 들어가, `../photo` + U+202E + `gpj.js` 같은 항목은 U+202E 뒤 글자가 거꾸로 그려져 화면에 `../photosj.jpg`로 보인다. 사용자가 D-029에서 정한 "제어 문자를 `\x0A`처럼 보이게"의 범위가 좁게 적힌 것이다.
- 안 A ★: 1절에 용어 **보이지 않는 글자** = U+0000~U+001F, U+007F~U+009F, U+202A~U+202E, U+2066~U+2069를 두고, `<항목>`에서 이 글자를 U+00FF 이하는 `\x` + 대문자 16진 두 자리(`\x0A` `\x7F` `\x85`), 그 위는 `\u` + 대문자 16진 네 자리(`\u202E`)로 바꾼다. 거부(2ⓑ)하는 글자는 그대로 U+0000~U+001F(U+007F는 Windows가 받으므로 대상, 예시 130 그대로). (c)도 같은 용어를 쓴다
- 안 B: 모두 `\u` + 네 자리로 통일. 승인된 예시 129 `a\x0Ab.js`가 `a\u000Ab.js`로 뒤집힌다(기능 변경)
- 안 C: 방향 문자는 바꾸지 않고 지운다. 무엇이 있었는지 문구에서 알 수 없다
- 추천 A: 승인된 예시를 그대로 두고 범위만 넓힌다. 바꾼 뒤 200자에서 자르는 규칙은 그대로(바꾼 표시 중간에서 잘릴 수 있다는 점도 지금과 같다)
- 덧붙임(바꾸지 않음): 보안규칙 5장의 `open(경로, "xb")`(NTFS 짧은 이름 `ABCDEF~1.JS`로 앞 파일을 덮어쓰는 것을 막음)에 걸리면 F-I01 예외의 "그 밖의 오류 → 점검 중 오류가 나서 멈췄습니다"로 읽힌다. 명세는 그대로 두고 예시 한 줄만 더한다(아래 예시 표)

**(e) 비교 화면 탭의 개수에 '정보'를 넣나 (SCR-05 05-03, F-C02 5) — 명확화, 총괄 대리 가능**

상황: 고쳐짐에 높음 S01-AWS 1개와 정보 S03-URL 1개가 있다. 정보는 기본으로 숨긴다(F-C02 5). 탭에 `고쳐짐 1`(보이는 줄 수)인지 `고쳐짐 2`(전부)인지 명세가 말하지 않는다. T10은 '정보 보기'를 따르게 만들었다(병합됨).
- 안 A ★: 탭 개수도 '정보 보기'를 따른다. 꺼짐 `고쳐짐 1`·목록 1줄, 켜짐 `고쳐짐 2`·2줄. 정보만 있는 묶음은 꺼짐이면 `고쳐짐 0`·`없습니다`
- 안 B: 탭 개수는 늘 전부(`고쳐짐 2`), 목록만 숨긴다. 숨은 것이 있다는 것은 보이지만 숫자와 줄 수가 다르다
- 안 C: 늘 정보를 뺀다(켜도 `고쳐짐 1`). 켰을 때 숫자와 줄 수가 다르다
- 추천 A: 숫자와 목록 길이가 늘 같고, 이미 병합된 구현 그대로라 코드가 바뀌지 않는다. 점수에 들어가지 않는 정보를 기본 숫자에서 빼는 것은 SCR-04 04-03(정보는 켜야 보임)과도 맞다

**(f) 주소 계정 가리기의 대소문자 (1절 '근거 조각' ㉡) — 명확화, 총괄 판단 (T18 보고서 '고른 것'에서 옴, 2026-11-20 총괄 반영 요청 때 추가)**

상황: T18 레인은 명세가 정하지 않은 ㉡의 `http(s)://`를 S01-URLCRED·F-S03 1처럼 대소문자를 구분해 만들었다. 그러면 `HTTPS://admin:pw1234567@internal.myapp.kr`은 URLCRED 발견도 없고(규칙 표 정규식이 소문자만), 옆 AWS 발견의 근거 조각에도 `HTTPS://admin:pw1234567@…`가 원문으로 남는다(`pw1234567`은 9자라 ③도 못 덮는다). 브라우저는 `HTTPS://`도 받는다. 문서는 '명확화로 D-032에 넣기'를 하지 않았다 — 원문이 남는 쪽을 명세로 굳히게 되기 때문이다.
- 안 A ★: ㉡만 `http(s)://`를 대소문자 무시로 본다. 발견 규칙(S01-URLCRED, F-S03 1)은 그대로(규칙 버전 `r1` 그대로). `k="AKIAIOSFODNN7EXAMPLE" u="HTTPS://admin:pw1234567@internal.myapp.kr"` → AWS 근거 조각 `k="AKIA****LE" u="HTTPS://****@internal.myapp.kr"`
