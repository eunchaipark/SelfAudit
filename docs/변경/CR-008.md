## 바뀌는 것 (앞 문서부터)

### (1) 검토 방식 줄이기 — 사용자 결정 (설계 8.1)
- 상황: 검토 에이전트 둘이 같은 diff를 따로 읽고, 낮음까지 반려에 묶여 반려 한 번의 일 대부분이 낮음이었다. 재검토가 새로 찾은 높음·중간 둘은 모두 고친 범위 안이었다.
- 바뀌는 것: 병합 전 검토는 `task-reviewer` 하나, 반려는 높음·중간·검사 실패만, 낮음은 후속, 재검토는 고친 범위만. 등급의 중간에 '실험 결과를 비틀 수 있음'·'예시 테스트 없음'. 두 쪽 모두 보고 전에 스스로 잰다. 독립 검토도 하나를 두 쪽에(쌍 A는 병합 커밋 `f6e5aad`·`c23d5bb`에서), 한 세션 쪽 독립 검토는 보정 배치 전.
- 근거: 설계 8.1 표. 하나로 합쳐 놓치는 것은 **추정** — 쌍 B·C·D 독립 검토가 남은 높음·중간을 찾으면 검토 지시를 고친다. 독립 검토 차례·한 세션 쪽을 배치 전에 보는 것은 총괄 대리(같은 자·경계 결함이 공개 저장소로 새지 않게).

### (2) 첫 실험 N = 2 — 사용자 결정 (설계 8.2)
- 상황: 첫 실험은 번들 6 × A·B × 3 = 36번이었다.
- 바뀌는 것: 6 × 2 × 2 = 24번. 난이도마다 두 차례 재현율 차이가 어느 한 조건이라도 20%p를 넘으면 그 난이도 번들 둘을 A·B 모두 셋째(많아야 12번 더 → 36번). 셋째 뒤에는 더 돌리지 않고 A·B 범위가 겹치면 '차이를 말할 수 없음'. N = 5는 넓히기 때 사용자 확인.
- 근거: 20%p는 앞서 정한 N 기준과 같은 값(그 값은 그대로 총괄 대리, 사용자 확인 전). 두 값이 20%p 안이면 셋째가 가운데 값을 그 안에서만 움직인다. 잃는 것(두 번으로는 튄 값을 모름)은 R1 한계에.

### (3) 쌍 비교와 태스크 합치기 — 총괄 대리 (설계 8.1 '질문 2에 주는 영향', 8.3)
- 상황: 쌍 A(T23·T24)는 옛 방식으로 쟀고, 쌍 B부터는 새 방식이다. 남은 태스크 11개.
- 바뀌는 것: 방향 판정은 같은 방식의 쌍 B·C·D(쌍 D를 더함), 쌍 A는 R2에 따로. `ops/측정.csv` `검토방식` 칸. 태스크 11 → 8(T28·T33·T35 합침, 첫 실험·덧붙임 계획은 명령으로) — 태스크는 총괄.
- 근거: 섞어 세면 방식 차이와 검토 방식 차이가 한 숫자에 섞인다. 3쌍 바닥(D-037)은 그대로라 D를 못 하면 A·B·C로 판정하고 한계에 적는다.

### (4) 첫 실험 전 번들 고침과 계약 선택 칸 — 총괄 대리 (설계 8.4)
- 상황: normal·hard 결과물에 원본 이름(`PAY_TAIL` 등)이 남음 / 줄로 가를 수 없는 위치 67곳 가운데 8곳은 그 파일에 정답 닻이 없어 사실상 맞힐 수 없음 / easy에 `comment` 미끼, normal에 `split` 미끼 없음 / 16진 미끼 60·62자 대 정답 32자 / 줄로 가를 수 없는 위치의 닻이 64자 넘는 것 8개.
