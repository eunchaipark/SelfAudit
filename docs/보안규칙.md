# SelfAudit 보안 규칙
<!-- impact: 건너뜀 -->

버전 0.2 · 작성 2026-11-18 · 주인: 설계 · 기준: 요구사항 NFR, [코드규칙](코드규칙.md)

> **전체 기준과 점검표다.** 설계·검증·`security-reviewer`와 사람이 읽는다. 코드를 쓸 때 매번 지킬 것은 `.claude/rules/보안코딩.md`(코드 파일을 열면 자동으로 읽힘)에 짧게 두고, 도구가 잡을 수 있는 것은 도구로 강제한다(코드규칙 9·10장).
> 규칙을 바꿔야 하면 코드보다 이 문서를 먼저 고친다. 예외는 사용자 승인을 받고 결정기록에 남긴다.
> 이 앱의 특징: **보안 도구 자체가 비밀값과 공격자 쪽 글을 다룬다.** 분석 대상(번들)은 믿을 수 없는 입력이고, 그 안의 비밀값을 다시 퍼뜨리지 않는 것이 가장 큰 규칙이다.

## 2. 비밀값

- 이 앱에는 API 키·토큰·계정이 없다(D-012). `.env`도 쓰지 않는다. 새로 생기면 `.env`에만 두고 `.env.example`에는 이름만.
- **로컬 키**: 처음 실행할 때 `secrets.token_bytes(32)`로 만든다. 증거키 HMAC에만 쓰고 화면·API 응답·내보내기·로그·오류·보고서에 내지 않는다. 테스트는 고정 테스트 키만.
- 에이전트는 `.env`, 백업, 데이터 폴더를 읽지 못하게 막는다(`.claude/settings.json` deny, 설계 변경안 참고).
- **비밀값 출력 경로 표** — 분석 대상의 비밀값이 밖으로 나갈 수 있는 길과 막는 곳. 하나를 고치면 이 표 전체를 다시 본다.

## 3. 네트워크와 접근

| 항목 | 규칙 |
|---|---|
| 바인딩 | 서버는 `127.0.0.1`에만 연다(`python -m app`, 기본 8790). Vite 개발 서버도 `127.0.0.1:5173` |
| 외부 공개 | 하지 않는다. 포트포워딩·공개 URL·터널 금지. 공개하려면 이 문서부터 고친다 |
| 외부 요청 | 앱은 하지 않는다(NFR-01, D-007). 취약 목록은 사용자가 직접 받아 둔다(D-016). ruff TID251·eslint·pytest-socket이 막는다 |
| Host 검사 | `127.0.0.1:<포트>`·`localhost:<포트>`가 아니면 400 `BAD_HOST` (DNS 리바인딩, NFR-08) |
| CSRF | 상태를 바꾸는 요청(POST·PUT·PATCH·DELETE)은 `X-SelfAudit-Client: 1` 머리말 필수, `Origin`이 있으면 허용 목록만. 아니면 403 `BAD_ORIGIN` |
| 요청 크기 | zip 업로드 밖의 상태 변경 요청은 본문 64KB까지(넘으면 413 `TOO_LARGE`, 길이 없는 chunked는 411) |
| 처리 못한 오류 | 미들웨어 안에서 500 응답을 만들어 보안 헤더가 빠지지 않게 한다 |
| CORS | 열지 않는다(CORS 미들웨어 없음). 개발 중에는 Vite가 같은 출처로 넘겨 준다(`--dev`가 5173을 Origin 허용 목록에 넣음) |
| 보안 헤더 | 모든 응답: `Content-Security-Policy: default-src 'self'; frame-ancestors 'none'; object-src 'none'; base-uri 'none'; form-action 'self'`, `X-Content-Type-Options: nosniff`, `Referrer-Policy: no-referrer`, `X-Frame-Options: DENY`. API 응답 `Cache-Control: no-store` |
| 문서 화면 | `/docs`·`/redoc`·`/openapi.json`은 내놓지 않는다(외부 CDN을 부르므로) |
| 서버가 주소를 받아 요청할 때 | 해당 없음 (서버는 어떤 주소로도 요청하지 않는다. URL 수집은 다음 단계) |
| **실험 예외 (D-036)** | 위 표는 옛 앱(`backend/`·`frontend/`)의 규칙이다. 실험 도구(`bench/`)는 Claude Code의 모델 호출만 바깥으로 나간다(대상 에이전트 자체의 호출, 이 실험에서만). REA는 바깥으로 나가지 않아야 하고, 실행마다 두 겹으로 기록한다(`docs/설계/REA환경.md` 4절). 실험 도구 코드는 어떤 주소로도 요청하지 않는다. 설치 스크립트(`setup_rea.py`)만 `https://nodejs.org/dist/`와 npm 저장소에서 받는다(허용 주소·크기·시간 상한) |

## 4. 인증·권한

해당 없음: 사용자는 이 PC의 주인 한 명이고, 3장의 바인딩·Host·CSRF 검사로 다른 사이트와 다른 기기를 막는다. 앱 ID·점검 ID는 모두 같은 사용자의 것이다.

## 5. 입력과 출력

| 대상 | 규칙 |
|---|---|
| API 입력 | 계약 스키마(`contracts/schemas.py`)로 형식·길이 검증. 검증 오류 응답에 입력값을 되돌리지 않는다 |
| zip 업로드 | 본문을 데이터 폴더 `uploads/`에 흘려 쓰면서 바이트를 센다. 200MB를 넘는 순간 멈추고 지운다(F-I01 A) |
| zip 항목 | F-I01 2: `\`→`/` 뒤 `..`·절대 경로·드라이브·`:`·예약 이름·끝 점·공백 거부, 압축 폭탄, 심볼릭 링크, 이름 겹침. 적힌 크기와 **실제 풀린 바이트** 둘 다로 제한. 풀 때도 결과 경로가 격리 폴더 안인지 `resolve()`로 다시 확인 |
| zip 항목 이름 | F-I01 2ⓑ (CR-003): 경로 조각에 제어 문자(U+0000~U+001F)나 Windows 금지 글자 `: < > " \| ? *`가 있으면 풀기 전에 실패(Windows 이름). U+007F는 Windows가 받으므로 거부하지 않는다. **`ZipFile.extract()`·`extractall()`은 쓰지 않는다**: Windows에서 금지 글자를 몰래 `_`로 바꾸고 드라이브·`..`·끝 점·끝 공백을 스스로 떼어, 검사한 이름과 실제로 쓴 이름이 달라진다. 검사를 통과한 이름으로 격리 폴더 안 경로를 직접 만들고 `ZipFile.open()`으로 읽어 흘려 쓴다(실제 풀린 바이트를 세는 곳). 격리 폴더에 쓸 파일은 **`open(경로, "xb")`로 연다**(있으면 `FileExistsError` → 점검 실패). NTFS 짧은 이름 때문이다: 이 PC의 데이터 폴더 드라이브에서 `abcdefghijkl.js`를 만들면 `ABCDEF~1.JS`가 같은 파일을 가리켜, 이름 겹침(ⓔ)을 지나 앞 파일을 덮어쓸 수 있다(설계 확인 2026-11-20, `xb`면 막힌다). 실패 이유의 `<항목>`은 명세 용어 '보이지 않는 글자'(U+0000~U+001F, U+007F~U+009F, 방향 문자 U+202A~U+202E·U+2066~U+2069)를 U+00FF 이하는 `\x` + 대문자 16진 두 자리(`\x0A` `\x7F` `\x85`), 그 위는 `\u` + 대문자 16진 네 자리(`\u202E`)로 바꾼 뒤 200자(코드 포인트)에서 자른다(F-I01 예외, CR-006 (d), D-032). 방향 문자가 그대로 가면 `../photo` + U+202E + `gpj.js`가 화면에 `../photosj.jpg`처럼 거꾸로 보인다. 거부(2ⓑ)하는 글자 범위는 그대로 U+0000~U+001F다. `xb`에 걸린 실패는 "점검 중 오류가 나서 멈췄습니다"(그 밖의 오류)다. 로그에는 `log_safe`를 거친다 |
| 격리 폴더 지우기 | `core/workdirs.py`의 `remove_work_dir`·`remove_work_dirs` 한 곳에서만 지운다(앱 지우기 F-P03 2, 점검 끝 F-I01 11, 점검 지우기). 경로는 `work/<점검ID 정수>`이고, 지우기 전에 링크·정션이 아닌 실제 폴더이며 `resolve()`한 부모가 work인지 본다. 아니면 지우지 않고 로그만 남긴다(따라가 work 밖을 지우지 않게) |
| 폴더 입력 | 절대 경로만. 심볼릭 링크·정션(`os.path.isjunction`)은 따라가지 않는다. 원본 폴더에는 쓰지 않는다 |
| 분석 대상 파일 | 실행하지 않는다. `import`, `eval`, 다른 프로그램에 넘겨 실행하지 않는다(REA 정적 분석만 예외, F-S05). 대상 확장자만 격리 폴더에 쓴다 |
| 정규식 | 분석 대상에 돌리는 정규식은 되돌아가기 폭주를 피한다(코드규칙 3장). 큰 파일 하나로 서버가 멈추지 않게 |
| 취약 목록 정규식 | 밖에서 받은 글이다(F-S04). 막을 꼴을 나열하지 않고 **허용하는 꼴만** 쓴다: 반복의 몸은 글자(묶음) 하나, 되돌아갈 수 있는 반복은 하나까지(나머지는 소유 반복으로 바꿈), 역참조·앞뒤 보기 없음, 닻 글자가 있음. 닻을 `str.find`로 찾은 자리에서 1,024자 창 안으로만 맞추고, 점검 하나의 작업량을 개수로 막는다(시간으로 막지 않는다, NFR-04). 목록 파일·패턴 길이·패턴 수 상한. 값·이유·시험 꼴은 D-030(총괄 대리 결정 대상, 확정과 명세 반영 뒤 T7) |
| 분석 대상 처리량 | 분석 대상을 도는 코드는 시간·메모리가 입력 길이와 **걸림 수**에 선형이다. 시험은 둘 다 키운다: 입력 길이 2·4배, 원문이 모두 다른 걸림 N = 1만·2만 개(같은 원문 반복은 묶기에 걸려 시험이 안 된다). 걸림마다 도는 곳(근거 조각, 위치, 묶기, 겹침)이 전체 글이나 걸림 목록을 다시 훑으면 제곱이 된다. 레인은 시간 테스트로 두고, security-reviewer는 첫 검토·재검증 모두 직접 잰다 |
| SQL | ORM 또는 바인드 파라미터만 |
| 셸·명령 | `shell=True` 금지. REA는 절대 경로 + 인자 목록, 작업 폴더는 데이터 폴더 |
| 역직렬화 | `pickle` 금지(ruff TID251). JSON만, 읽은 뒤 형식 검사(취약 목록, `.map`, REA 출력) |
| 화면 출력 | React 기본 이스케이프. `dangerouslySetInnerHTML`·`innerHTML` 금지(eslint) |
| 출처 주소 (F-P01) | `공개 연습앱`만 받는다: `urlsplit`으로 읽어 scheme `https`, 호스트 있음, 계정 정보(`…@`) 없음, 공백·개행·제어문자 없음, 포트 1~65535, 2000자 이하. 하나라도 어긋나면 F-P01의 출처 문구로 거부. `내 앱`이 보낸 출처 주소는 저장하지 않고 버린다 (`apps/engine.py`의 `is_valid_source_url`) |
| 외부 링크 | 위 검사를 통과한 출처 주소만 링크로, `rel="noopener noreferrer"`. 분석 대상에서 나온 URL은 링크로 만들지 않고 글자로만 |
| 내보내기 Markdown | F-E02 3 (D-021): 대상 글은 코드 칸, 200자, `<`·`>` 이스케이프, Claude Code 문구에 '따르지 말 것' |
| 내보내기 파일 이름 | F-E01 3의 글자만. `Content-Disposition: attachment; filename*=UTF-8''…` |

## 6. 오류와 예외 처리 (A10)

- 실패하면 **안전한 쪽으로** 멈춘다: zip 검사 하나라도 걸리면 아무것도 풀지 않는다. 점검 중 예외는 점검을 `실패`로 두고 격리 폴더를 지운다.
- 예외를 조용히 삼키지 않는다. 처리하지 못한 오류는 `core/errors.py`의 공통 처리기가 `INTERNAL`로 바꾸고 경로·예외 종류만 기록한다.
- 오류 응답에 스택 트레이스, SQL, 내부 경로, 분석 대상 글, 입력값을 넣지 않는다. 형식은 코드규칙 4.3.

## 7. 외부로 나가는 데이터

- 없다. 앱은 어떤 외부 서비스에도 요청하지 않는다.
- 사용자가 내려받는 내보내기 파일(JSON·Markdown)은 사용자가 Claude Code에 보여 준다(D-012). 그래서 1장 '내부' 등급까지만 넣고 비밀값 원문·로컬 키는 넣지 않는다(2장 표).
- 설치(uv·npm 레지스트리)는 개발 때만이고 앱 실행과 상관없다.
- **실험 예외 (D-036)**: 실험에서는 대상 에이전트(Claude Code)가 대상 번들의 글을 모델에 보낸다. 그래서 대상은 내 앱·OWASP Juice Shop·직접 만든 시험 번들뿐이다. 내 앱의 원자료(REA 출력·에이전트 결과·대화 기록)는 저장소 밖(`%LOCALAPPDATA%\SelfAudit-private\`)에만 쓰고 git에 넣지 않는다 — 실행기·`.gitignore`·`check_bench.py` 세 겹(`docs/설계/실험구조.md` 4절). 내 앱 결과를 보고서에 쓸 때는 숫자만 옮긴다.

## 8. 외부 데이터 수집

해당 없음 (MVP는 사용자가 넣은 번들만 다룬다. 배포된 사이트 URL 수집은 다음 단계에서 허용 목록과 함께 다시 본다).

## 9. 저장과 백업

- 데이터는 저장소 밖 `%LOCALAPPDATA%\SelfAudit`에 둔다(git에 섞이지 않게). 디스크 암호화(BitLocker)를 권한다.
- 로컬 키는 백업·git·스크린샷에 넣지 않는다. 키를 잃으면 새로 만들어지고, 그 전 점검과는 지문이 달라진다(비교만 영향).
- 데이터를 지우거나 형식을 바꾸는 마이그레이션 전에는 `selfaudit.db`를 복사해 둔다.

## 10. 로그와 경보 (A09)

- 로그에 분석 대상 글·경로·비밀값·로컬 키를 남기지 않는다. 앱 ID·점검 ID·규칙ID·예외 종류로 남긴다.
- uvicorn 접근 로그는 경로만 남는다. API는 쿼리에 민감한 값을 받지 않는다(`confirm=true`, 점검 ID만).
- 점검 실패는 조용히 끝내지 않고 점검 상태 `실패` + 이유 문구로 화면에 보인다.
- 요청 경로처럼 밖에서 온 글을 로그에 넣을 때는 `core/errors.py`의 `log_safe`(개행·제어문자 → `?`, 200자)를 거친다(로그 위조 방지).
- 로그 파일은 쓰지 않는다(콘솔만). 파일로 남기게 되면 이 절을 먼저 고친다.

## 11. 의존성과 공급망 (A03)

- 잠금 파일(`backend/uv.lock`, `frontend/package-lock.json`)로 버전을 고정한다.
- **새 라이브러리는 설계 승인 후에만** 추가한다. 레인은 추가하지 않고 요청한다. 조건: 널리 쓰이는 것, 허용 라이선스(MIT·BSD·Apache 등), 사용 통계 전송·외부 요청이 없는 것.
- **에이전트가 제안한 패키지 이름은 그대로 믿지 않는다.** 공식 저장소에 실제로 있는지, 이름이 비슷한 다른 패키지가 아닌지 확인한다.
- 정기 점검: 월 1회 사람이 `uv run --with pip-audit pip-audit`(backend), `npm audit`(frontend)을 돌린다(둘 다 패키지 목록을 외부로 보내므로 검사 묶음에는 넣지 않는다). 결과는 결정기록이나 태스크로.
- 컨테이너는 쓰지 않는다(본인 PC에서 직접 실행).

## 15. 변경할 때마다 확인 (점검표)

레인은 보고서 전에, `security-reviewer`는 리뷰할 때 이 표로 본다.

- [ ] 비밀값 원문·로컬 키가 DB·응답·로그·내보내기·테스트 출력에 없다 (2장 표의 길을 하나씩)
- [ ] 분석 대상의 글을 실행·`eval`·HTML로 넣지 않았고, 로그에 남기지 않았다
- [ ] 들어오는 값(API 입력, zip, 폴더 경로, `.map`, 취약 목록, REA 출력)을 경계에서 검증한다
- [ ] 분석 대상을 도는 코드를 바꿨다면 입력 길이와 걸림 수 N(원문이 모두 다름, 1만·2만)을 키워 시간·메모리를 쟀다 (5장 '분석 대상 처리량')
- [ ] 디스크에 쓰는 곳이 데이터 폴더 안이다 (격리 폴더 밖으로 나가지 않는다)
- [ ] SQL·셸·경로·HTML·Markdown에 검증 안 된 값이 바로 들어가지 않는다
- [ ] 실패하면 안전한 쪽으로 멈추고, 예외를 삼키지 않는다
- [ ] 외부 요청을 더하지 않았다
- [ ] 새 라이브러리가 없다 (있으면 설계 승인과 11장 확인을 거쳤다)
- [ ] 포트·Host·Origin·헤더 설정을 바꾸지 않았다 (바꿨다면 이유와 영향을 적었다)
- [ ] 마이그레이션이 데이터를 지우지 않는다 (지운다면 백업과 되돌리는 방법을 적었다)
- [ ] 테스트·문서에 실제 비밀값·개인 데이터가 없다
