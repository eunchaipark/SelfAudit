# <프로젝트> 코드 규칙

버전 0.1 · 작성 <날짜> · 주인: 설계 · 기준: 요구사항, 기능명세, 화면정의, [보안규칙](보안규칙.md)

> **전체 기준이다.** 설계·검증과 사람이 읽는다. 레인은 이 문서를 통째로 읽지 않는다.
> 코드 표준은 세 겹으로 둔다: **도구 설정**(자동으로 잡음) → **경로 규칙** `.claude/rules/`(해당 파일을 열면 자동으로 읽힘) → **이 문서**(이유와 전체). 도구가 잡을 수 있는 것은 글로 다시 쓰지 않는다.
> 이 규칙과 다르게 해야 할 이유가 생기면 코드보다 이 문서를 먼저 고친다(설계). 레인은 고치지 말고 보고서 '요청' 칸에 적는다.

## 0. 채우는 법 (설계, 단계 2)

- `<…>` 칸을 프로젝트에 맞게 채운다. 적혀 있는 기본값은 이 PC의 SeedLog·Portfolio에서 쓰는 것이다.
- 규칙을 바꾸면 **같은 날 세 곳을 맞춘다**: 도구 설정, 경로 규칙, 이 문서. 어디에 무엇이 있는지는 10장 표.

## 1. 원칙

1. **명세가 먼저다.** 모든 코드는 기능 ID(F-…)에 대응한다. 명세에 없는 동작은 만들지 않는다. 명세와 다르게 만들어야 하면 멈추고 변경 요청으로.
2. **계산은 엔진에서, 엔진은 순수하게.** 계산·판정은 엔진에만 둔다. 엔진은 DB·네트워크·현재 시각·전역 난수를 쓰지 않는다.
3. **바깥과 닿는 곳은 한 군데씩.** 외부 API는 `clients/`, DB는 `db/`만 거친다. 화면은 외부 API를 직접 부르지 않는다.
4. **바뀔 수 있는 값은 설정에서.** 매직 넘버를 쓰지 않는다.
5. **본보기 기능의 모양을 따른다.** 새 모양이 필요하면 설계에 요청한다.
6. **도구가 잡는 것은 도구에 맡긴다.** 형식·import 순서·타입·흔한 실수는 `python ops/scripts/check.py`가 잡는다.

## 2. 폴더·파일

### 2.1 저장소 맨 위
| 경로 | 내용 |
|---|---|
| `backend/` | 서버 (<예: FastAPI>) |
| `frontend/` | 화면 (<예: React + TypeScript + Vite>) |
| `config/` | 설정 기본값 (코드에 쓰지 않는 기준값) |
| `docs/` | 명세·규칙 |
| `ops/` | 운영 파일 (역할 카드, 양식, 스크립트) |
| `scripts/` | 개발·운영 보조 스크립트 |

### 2.2 모듈 이름 표 (레인 경계가 여기서 정해진다)
| 영역 | 서버 | 화면 | 테스트 | 레인 | 명세 ID |
|---|---|---|---|---|---|
| <돈> | `backend/app/<money>/` | `frontend/src/features/<money>/` | `backend/tests/<money>/` | <돈> | <F-A> |
| 공통 | `backend/app/core/` | `frontend/src/app/`, `frontend/src/components/` | `backend/tests/core/` | (설계) | - |

### 2.3 새 기능을 만들 때 만들거나 고칠 파일 (본보기 기능 기준)
| 순서 | 파일 | 하는 일 |
|---|---|---|
| 1 | `backend/tests/<영역>/test_<기능>.py` | 명세 예시 테스트 (먼저) |
| 2 | `backend/app/<영역>/engine.py` | 순수 계산 |
| 3 | `backend/app/<영역>/service.py` | 흐름: 읽기 → 엔진 → 저장 |
| 4 | `backend/app/<영역>/api.py` | 입력 검증, 응답 |
| 5 | `frontend/src/features/<영역>/…` | 화면 |
본보기 기능: <기능 ID와 파일 위치>

### 2.4 표에 없는 위치
만들지 않는다. 레인은 '요청'으로 올리고, 설계가 이 표부터 고친다.

## 3. 공통 규칙

| 항목 | 규칙 |
|---|---|
| 언어 | 식별자는 영어. 주석·문서 문자열·사용자 문구는 한국어 |
| 추적성 | 서비스·엔진 함수의 문서 문자열 첫 줄에 기능 ID. 예: `"""F-A01 순자산 (FR-101)."""` |
| 주석 | "왜"만 쓴다. "무엇"은 코드로 드러낸다 |
| TODO | 기능 ID를 붙인다. 예: `# TODO(F-B08): 환율 환산` |
| 함수 | 작게, 하나의 일. 이른 반환으로 중첩을 줄인다 |
| 매직 넘버 | 금지. 기준값은 설정, 상수는 이름 있는 상수 |
| 파일 인코딩 | 항상 `encoding="utf-8"` (Windows 기본 cp949 때문) |
| 시간 | 시간대를 명시한다 (<예: Asia/Seoul>). 현재 시각은 주입받는다 |
| 돈·숫자 | <예: 금액은 원 단위 정수, 비율은 Decimal>. 반올림은 한 곳에서만 |
| 죽은 코드 | 남기지 않는다. 주석 처리한 코드도 지운다 (git에 남아 있다) |

## 4. 서버

### 4.1 계층
| 계층 | 할 일 | 하지 않을 일 |
|---|---|---|
| api | 입력 검증, 서비스 호출, 응답 스키마 | 계산, DB 직접 접근, 외부 호출 |
| service | 흐름과 트랜잭션 경계 | 계산 규칙 직접 구현 |
| engine | 순수 계산. 입력·출력은 불변 모델 | DB, 네트워크, `now()`, 전역 난수 |
| client | 바깥과 데이터 주고받기, 형식 검사, 내부 모델로 변환 | 비즈니스 판단 |
| db | 모델, 저장소 | 비즈니스 판단 |

### 4.2 DB
- 스키마 변경은 마이그레이션으로만. 마이그레이션은 한 번에 한 태스크만 만든다(관제가 줄 세움).
- 데이터를 지우거나 형식을 바꾸는 마이그레이션은 커밋 설명에 영향과 되돌리는 방법을 적고, 운영 데이터에 적용하기 전에 백업한다.
- 쿼리는 ORM 또는 바인드 파라미터로만.

### 4.3 API
- 경로 `<예: /api/v1/...>`, 자원 이름은 복수형 명사.
- 오류 응답 형식 하나: `{"code": "VALIDATION_FAILED", "message": "사용자에게 보일 문장"}`. 스택·SQL·개인 값은 넣지 않는다.
- 화면에 필요한 계산도 서버 API로 한다. 화면에서 같은 계산을 다시 만들지 않는다.

### 4.4 외부 호출
- 출처별 모듈 하나(`clients/`). 시간 제한 필수(<예: 10초>), 재시도 횟수 제한, 429·차단이면 멈춤.
- 응답은 형식·값 범위를 검사한 뒤 내부 모델로 바꾼다. 테스트는 녹화한 가짜 응답으로만.

### 4.5 오류·로그
- 도메인 오류는 공통 오류 클래스를 상속하고 `code`를 가진다. 예외를 조용히 삼키지 않는다.
- 로그에는 ID와 출처 이름만. 개인 값·비밀값·키가 붙은 URL은 남기지 않는다([보안규칙](보안규칙.md) 10장).

## 5. 화면

### 5.1 구조
| 폴더 | 내용 |
|---|---|
| `features/<영역>/` | 영역별 화면·구성 요소 (레인 경계) |
| `components/` | 공통 구성 요소 (설계) |
| `api/` | API 스키마에서 생성한 타입, 데이터 훅 (손으로 같은 타입을 다시 정의하지 않는다) |
| `lib/format.ts` | 숫자·날짜 표시는 여기서만 |

### 5.2 규칙
- 서버 상태는 <예: TanStack Query>로만. 화면 안에 계산을 다시 구현하지 않는다.
- 색·간격·글꼴은 디자인 토큰만 쓴다. 구성 요소에 색 코드를 직접 쓰지 않는다.
- 진짜 `<button>`, `<a href>`, `<label>`. 누르는 영역 44px 이상, 글자 대비 4.5:1 이상.
- 외부 텍스트는 일반 텍스트로만 보인다. `dangerouslySetInnerHTML` 금지(도구가 잡음).
- 화면을 만들면 <예: 1360·768·390px>에서 확인한다(검증 세션).

## 6. 테스트

| 종류 | 규칙 |
|---|---|
| 명세 예시 테스트 | 필수. 기능명세의 예시를 숫자 그대로 옮긴다. 예시가 없는 계산은 경계값 1~2개 |
| 외부 응답 변환 | 녹화한 응답(키·개인 값 없이)으로 변환만 확인. 실제 호출 금지(네트워크 차단) |
| 보안 기본 | 비밀값 노출, 오류 응답 모양, 보안 헤더 테스트를 뼈대에서 만들고 유지 |
| 이름 | `test_<기능ID>_<상황>` (예: `test_F_A01_예시합계`) |
| 언제 | 코드를 쓰는 동안은 지금 기능의 테스트만. 끝에 `check.py` 전체 한 번 |
| 기대값 | 통과시키려고 바꾸지 않는다. 예외는 `변경: CR-n` 태스크의 testStrategy에 적힌 테스트뿐 |
| 두지 않는 것 | <예: 커버리지 기준, 기능마다 화면 컴포넌트 테스트>. 버그가 반복되면 그때 더한다 |

## 7. Git과 작업 단위

- 로컬 저장소 기준. 기본 브랜치 `main`, main을 움직이는 것은 총괄뿐.
- 태스크 하나 = 브랜치 하나: `task/<id>-<짧은이름>`. 검증은 `verify/b<n>`.
- 하위 작업마다 커밋: `[T<id>.<n>] 한 줄 요약`. 변경 요청 태스크는 `(CR-n)`을 붙인다. 역할 커밋은 `[관제]`, `[문서]`, `[설계]`.
- 커밋은 내 파일만 경로를 적어서: `git commit -m "..." -- <파일들>`. `git add -A` 금지.
- 되돌리기: 하위 작업은 `git revert`, 태스크 전체는 브랜치를 병합하지 않는다. 기록을 지우는 명령(`reset --hard`, 강제 push)은 사용자 확인 후에만.

## 9. 도구 설정 (기본값)

**서버 (Python)** — `backend/pyproject.toml`
```toml
[tool.ruff]
line-length = 100

[tool.ruff.lint]
preview = true
explicit-preview-rules = true
# S: 보안 검사(bandit), DTZ: 시간대 없는 시각, PLW1514: 파일 인코딩 명시
select = ["E", "F", "W", "I", "B", "UP", "SIM", "RUF", "N", "S", "DTZ", "PLW1514"]
ignore = ["RUF001", "RUF002", "RUF003", "S101"]  # 한국어 문장 부호, 테스트 assert

[tool.ruff.lint.per-file-ignores]
"tests/**" = ["S105", "S106", "S107", "N802"]  # 가짜 값, test_F_A01_ 같은 이름

[tool.mypy]
strict = true

[tool.pytest.ini_options]
addopts = "--allow-hosts=127.0.0.1,::1"  # pytest-socket: 외부 접속 차단
```

**화면 (TypeScript)**
- `tsconfig.json`: `"strict": true`, `"noUncheckedIndexedAccess": true`, `"noUnusedLocals": true`, `"noUnusedParameters": true`
- `eslint.config.js`: `@eslint/js` recommended + `typescript-eslint` recommended + `eslint-plugin-react-hooks`, 그리고 금지 규칙:
  ```js
  'no-restricted-syntax': ['error',
    { selector: "JSXAttribute[name.name='dangerouslySetInnerHTML']", message: 'dangerouslySetInnerHTML 금지 (보안규칙 5장)' },
  ]
  ```
- `.prettierrc`: `{ "singleQuote": true, "printWidth": 100 }`

**검사 묶음** — `ops/checks.json`에 위 도구 명령을 모두 넣는다(린트, 형식 확인, 타입, 테스트, 빌드). 도구가 있으면 의존성 검사(`pip-audit`, `npm audit`/`pnpm audit`)와 비밀값 검사(gitleaks 등)도 넣는다.
