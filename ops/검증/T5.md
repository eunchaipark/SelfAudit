## 반려 사유 (재현은 직접 했다)
**[중간 1] S01-JWT 정규식이 입력 길이의 제곱으로 느려진다** — `backend/app/rules/secrets.py:62-64`
- 재현(`cd backend`):
  ```
  uv run python -W ignore -c "import time; from app.rules import secrets as s; k=b'k'*32
  for n in (20000,40000,80000):
      t=time.time(); s.scan_file('a.js','eyJ-'*(n//4),k); print(n, round(time.time()-t,2))"
  ```
  → 20KB 0.32초, 40KB 1.39초, 80KB 4.97초. 두 배가 되면 약 4배.
- 원인: `\beyJ[A-Za-z0-9_-]{5,}`가 `-`·`_`까지 줄 끝까지 먹고 `.`을 못 찾아 되돌아가고, `-` 뒤의 `eyJ`마다 다시 시작한다. 한 줄로 압축된 번들 5MB면 사실상 멈춘다.
- 보고서의 "긴 식별자 폭주 없음" 테스트에 이 입력이 없다. 설계 보고가 미리 알린 위험(코드규칙 3장)을 JWT 규칙에서 놓쳤다.
- 고칠 방향: `eyJ`를 `str.find`로 찾아 그 자리에서만 매치하거나 첫 구간에 상한을 둔다. `eyJ-` 반복 입력 테스트를 더한다.

**[중간 2] 개인키 후보가 BEGIN마다 원문 조각을 복사한다** — `secrets.py:114-125`
- 재현: `s.scan_file('a.js','-----BEGIN PRIVATE KEY-----'*10000, b'k'*32)` → 270KB에서 tracemalloc 최대 44MB(입력의 약 160배). 선형이면 50MB 입력에 약 8GB. BEGIN이 여러 개이고 END가 맨 끝 하나뿐이면 시간도 제곱(56KB 0.12초 → 224KB 1.54초, 검토 측정).
- 원인: 후보마다 `content[m.start():end]`(최대 4096자)를 겹침 제거 전에 만든다.
- 고칠 방향: 후보에는 범위만 두고 받아들인 것에서만 원문을 만든다. 같은 END에 묶이는 중첩 BEGIN은 첫 것만 받는다.

## 보안 (security-reviewer, `main..verify/b1`): 높음 0 · 중간 3 · 낮음 4
- 중간 3건 중 2건은 위의 반려 사유. 세 번째:
  - [중간→명세 질문] 근거 조각 앞뒤 200자 창에 **발견되지 않은** 짧은 비밀(`var pw='hunter2'`, 따옴표 없는 `password = abc12345xyz`)이 AWS 발견의 근거 조각에 원문으로 남는다(`text.py:96-125`). 명세 ②는 "그 범위의 모든 **S01 걸림**을 가린다"이고 ③은 20자 이상만 가리므로 코드는 명세대로다. 판정에서 빠진 짧은 값은 가려지지 않는다. 허용할지 아니면 "키워드+구분자+값 꼴은 길이와 무관하게 가린다"로 바꿀지 문서·설계가 정한다. **이 건 자체는 반려 사유로 세지 않았다.**
- 낮음 4: `.map`의 `sources` 이름이 길이 제한·줄바꿈 치환·긴 문자열 가리기 전에 접두로 붙는다(`secrets.py:211-228`) / 근거 조각 표시 문자가 사설 영역 U+E000·U+E001이라 대상 글에 같은 글자가 있으면 조각이 잘못 잘린다(`text.py:29-30,122-123`) / `evidence_key`가 빈 키·짧은 키를 거르지 않는다(`text.py:33-36`) / `_Candidate.raw`가 기본 `repr`에 원문을 담는다(`secrets.py:85-91`, `field(repr=False)`).
- 좋은 점: 가린 값만 `Finding`에 나가고 증거키는 HMAC-SHA-256에 로컬 키를 인자로 받으며, 분석 대상을 실행하는 곳이 없고, 새 라이브러리·외부 주소가 없다. GENERIC·URLCRED·STRIPE와 긴 공백·식별자 입력은 선형(450KB 0.2초)이다. `.map` JSON 오류·깊은 중첩(10만)은 안전하게 빈 목록. 입력 크기 상한은 호출부(수집)가 거는지 확인이 필요하다.

## 반려 뒤 처리
- 통과로 남길 태스크가 없다. `verify/b1`은 병합 상태에 이 보고만 더했다. **main에 병합하지 않는다.**
