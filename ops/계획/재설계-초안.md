# 재설계 초안 — REA 중심 (총괄, 2026-11-21 밤, 사용자 확인 전)

## 사용자가 정한 것 (2026-11-21)
- 목적을 바꾼다. 이 프로젝트로 알고 싶은 것은 둘이다.
  1. REA(역설계 에이전트)를 쓰면 보안 점검 성능이 높아지는가
  2. 내가 만든 병렬 작업 방식(SessionKit)의 효율은 어떤가
- 설계는 "REA 중심으로 처음부터" 한다(총괄 추천 '실험대로 바꾸기'를 고르지 않음).
- REA는 설치한다(Node 업그레이드·설치는 사용자가 직접). 분석 대상이 내 앱과 허용된 연습앱뿐이므로 이 실험에서는 외부 AI 호출을 허용한다.
- 병렬 방식 효율은 비교군을 만들어 잰다.

## REA 조사에서 알게 된 것 (github.com/morluto/rea 문서, npm 페이지는 못 읽음)
- REA는 AI 에이전트(예: Claude Code)가 MCP로 부르거나 사람이 CLI로 쓰는 역설계 도구다. REA가 스스로 AI를 부르지는 않고, 판단은 그것을 쓰는 에이전트의 모델이 한다.
- 웹 쪽에 맞는 것: `rea analyze-javascript-application <폴더> --json` (JS·Electron 정적 분석, 모듈·import·라우트·엔드포인트·소스맵 관찰, 근거 위치·확신도). 비밀값·취약점 '스캐너'라는 말은 문서에 없다.
- Node 22.23.4 이상. Windows에서 JS 정적 분석이 되는지는 문서에 없고, 소스맵 원본 대조(historical-source import)는 Linux·macOS만 → 먼저 이 PC에서 돌려 보는 시험이 필요(안 되면 WSL).
- 공정한 비교에 걸리는 것: 결과가 실행마다 다를 수 있음(에이전트 모델 판단), 버전이 빨리 바뀜(버전 고정), `rea setup`이 클라이언트 전체에 등록돼 'REA 없음' 조건이 오염될 수 있음(설정 폴더 분리).

## 그러면 질문 1은 이렇게 잰다
"같은 AI 에이전트(Claude Code, 같은 모델·같은 지시)가 내 웹앱 빌드 결과물을 점검할 때, REA를 쥐여 주면 더 많이·더 정확히 찾는가"

| 조건 | 무엇 |
|---|---|
| A | Claude Code — 파일 읽기·검색 도구만 (REA 없음) |
| B | Claude Code + REA (MCP) |
| (C, 선택) | 사람이 짠 규칙 검사기 — AI 없는 바닥값. 지금까지 만든 비밀값·소스맵·내부 주소 점검 코드를 쓸 수 있다 |

- 대상: ① 정답지가 있는 시험 번들 — 문제를 일부러 심는다(평문·나눠 쓴·난독화된 비밀값, 소스맵, 내부 주소·관리 경로, 숨은 API 라우트, 화면에만 있는 권한 검사, 디버그 플래그, 옛 버전 라이브러리). 쉬움·보통·어려움 단계로 ② 허용된 공개 연습앱(OWASP Juice Shop 빌드) — 알려진 취약점 목록을 정답지로
- 같게 맞출 것: 모델, 지시문, 시간·토큰 상한, REA 버전, 같은 대상을 조건마다 N번 반복(결과가 흔들리므로)
- 결과 형식: 에이전트가 정해진 JSON(종류·파일·위치·근거)으로 내게 한다 → 채점기가 정답지와 맞춰 본다
- 숫자: 찾은 비율(재현율), 맞게 찾은 비율(정밀도), 걸린 시간, 토큰·비용, 위치를 정확히 짚었나, 단계별(쉬움·어려움) 차이

## 질문 2는 이렇게 잰다
- 이 실험 도구를 만드는 일 자체를 두 방식으로 나눠 만든다: 비슷한 크기의 작업 쌍을 골라 하나는 병렬(레인 + 검토 + 총괄), 하나는 한 세션이 나누지 않고 만든다.
- 둘 다 마지막에 같은 독립 검토를 한 번 더 돌려 '병합 뒤 남은 결함'을 센다.
- 숫자: 걸린 시간, 사용량(5시간·주간 %), 반려 수, 검토가 잡은 결함, 병합 뒤 남은 결함, 다시 한 일. 지금까지의 기록(ops/측정.csv, 검증 파일 13개)은 '병렬' 쪽 참고 자료로 쓴다.

## 만들 것 (지금보다 훨씬 작다)
1. 시험 번들 만들기와 정답지 (사람이 읽는 표 + 기계가 읽는 JSON)
2. 실행기: 조건 A·B(·C)로 대상마다 N번 돌리고 결과·시간·토큰을 모은다 (Claude Code를 명령줄로 부른다, 설정 폴더를 조건마다 분리)
3. 채점기: 결과 JSON ↔ 정답지 → 재현율·정밀도 등
4. 결과 보고서: 표·그래프 한 장 (웹 화면 5개는 필요 없다 — 보고서 페이지 하나면 된다)
5. 병렬 효율 기록·비교 보고서
