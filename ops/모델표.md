# 모델·노력 표 (총괄이 세션을 열 때 그대로 적용한다)

주인: 총괄. 바꾸려면 사용자에게 묻고 이 표를 고친 뒤, 문서에게 결정기록 한 줄을 넘긴다.
모델 이름은 앱의 모델 목록에 있는 것을 쓴다 (지금: `claude-opus-5-5`, `claude-sonnet-5-5`, `claude-haiku-5-5`).
노력: 낮음(low) · 중간(medium) · 높음(high) · 엑스트라(xhigh) · 최대(max)

## 세션

| 역할 | 일 | 모델 | 노력 | 이유 |
|---|---|---|---|---|
| 총괄 | 늘 | Opus | 중간 | 의도 파악이 가장 중요하지만, 한 번에 읽는 양이 작고 자주 깨어난다 |
| 문서 | 단계 1 명세 쓰기, 큰 '추가' CR | Opus | 높음 | 명세의 예시가 그대로 테스트가 된다 |
| 문서 | CR 분석·반영, 고침 | Sonnet | 중간 | 정해진 결정을 문서로 옮기는 일 |
| 설계 | 단계 2 기반 | Opus | 엑스트라 | 모두가 따르는 결정이고 되돌리기 비싸다 |
| 설계 | 명세 검토, CR 기술 검토, 요청 처리 | Opus | 높음 | 영향 판단 |
| 관제 | 분해 검토, 배치안, 상태 | Sonnet | 중간 | 병렬 판단은 스크립트가 한다 |
| 레인 | 보통 태스크 | Sonnet | 중간 | 명세 예시와 본보기를 따라 하는 일 |
| 레인 | 계산 엔진, 보안에 민감한 부분, 동시성 | Sonnet | 높음 | 틀리면 손해가 큰 곳 |
| 검증 | 배치 검증 | Sonnet | 높음 | 놓치면 뒤에서 더 비싸다 |

## 서브에이전트 (`.claude/agents/`의 `model`·`effort`에 이미 적혀 있다)

| 이름 | 모델 | 노력 |
|---|---|---|
| `security-reviewer` | Sonnet | 높음 (보안이 핵심인 배치는 부를 때 Opus로) |
| `spec-checker`, `task-planner` | Sonnet | 중간 |
| `doc-recorder` | Haiku | 낮음 |

## 적용 규칙

1. **열 때 바로 적용**: 총괄은 세션을 열 때 `model`과 `effort`를 표대로 넣는다. 앱은 총괄 자신의 모델·노력 **이하만** 바로 정하게 해 준다.
2. **총괄보다 높을 때**(예: 설계 엑스트라): 세션을 연 뒤 노력 바꾸기로 올린다. 앱이 사용자에게 한 번 묻는다. 비싼 세션을 사용자가 알고 여는 장치다.
3. **총괄 자신**의 모델·노력은 사용자가 앱에서 고른다(세션은 자기 모델을 바꿀 수 없다).
4. **자동으로 올리기**: 같은 태스크가 반려되면 그 레인의 노력을 한 단계 올린다(중간 → 높음). 두 번째 반려나 같은 오류 3번이면 Opus·높음으로 바꾼다. 태스크가 끝나면 표대로 되돌린다.
5. **자동으로 내리기**: 5시간 사용량이 70%를 넘으면 레인 '높음'을 '중간'으로, 새 Opus 세션은 미룬다. 검증은 '높음'을 지킨다.
6. **최대(max)는 쓰지 않는다.** 사용자가 직접 지시할 때만.
7. **기록**: 보드 세션 표에 모델·노력을 적고, 기록이 `ops/측정.csv`에 옮긴다. `retro.py`가 모델·노력별로 반려·교대를 모아 보여 준다. 회고에서 이 표가 맞았는지 보고 고친다.
