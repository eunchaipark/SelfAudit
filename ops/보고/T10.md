## 한 것
같은 앱의 완료된 두 점검을 비교하는 기능을 만들었다(F-C02). 고른 순서와 상관없이 시작 시각이 앞선 쪽을 '전'으로 두고, 지문(F-C01)마다 개수를 세서 고쳐짐·남음·새로 생김으로 나눈다. 점수 변화와 규칙 버전 알림도 낸다.

## 명세와 달라진 점
- SCR-05 05-01: 제목은 `<앱> · 전 <시각> → 후 <시각>`이어야 한다. 그런데 계약 `ComparisonOut`에 앱 이름이 없다. 지금은 `GET /scans/{beforeId}`가 501이라 제목에 앱 이름이 빠진다(아래 '요청').

명세가 정하지 않은 작은 부분은 아래처럼 골랐다.
- 예외는 명세 예외 칸의 차례대로 확인한다. 같은 점검 → (없는 점검 404) → 다른 앱 → 완료 아님. 거부는 모두 400 `VALIDATION_FAILED`다(공통 API 규칙)
- 같은 지문이 여러 개면 각 점검 안에서 저장된 순서대로 짝짓는다. 남음 항목에는 후의 발견(값·심각도)을 보인다
- 묶음 안의 정렬은 F-S06 3을 따르되, '경로'는 화면에 보이는 정규화 경로로 비교한다
- 지문은 DB의 `fingerprint` 칸을 쓰지 않고 F-C01 함수로 다시 계산한다. 그래야 F-C01이 바뀌어도 두 점검이 같은 기준으로 비교된다
- 탭에 보이는 개수도 정보 보기 설정을 따른다. 정보가 숨겨져 있으면 정보는 개수에서도 빠진다. 그래야 탭의 숫자와 목록 길이가 같다
- 불러오는 동안에는 문구 없이 빈 영역(`aria-busy`)만 둔다. 화면정의에 그때 쓸 문구가 없기 때문이다

## 문제와 개선

- 방법론: Bash 한 번에 여러 파일을 heredoc으로 쓰면 worktree 격리 검사가 명령을 거부한다 → 레인 카드 '함정'에 "파일은 Write로, git 명령은 따로"를 한 줄 적어 두면 시간을 덜 쓴다
- 프로젝트: SCR-05 제목에 앱 이름이 있는데 계약 `ComparisonOut`에는 앱 이름이 없다 → 화면정의와 계약을 맞춰 보는 단계에서 문구에 쓰는 값이 응답에 다 있는지 확인하면 좋겠다
- 방법론: 거부 오류 코드를 기능마다 새로 지어 공통 API 규칙과 어긋났고, 테스트도 `code`를 보지 않았다 → 레인 카드 '태스크 하나'의 테스트 단계에 "거부는 400 VALIDATION_FAILED, 테스트는 code까지 본다"를 한 줄 넣으면 좋겠다
