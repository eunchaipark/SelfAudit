### 고른 것 (근거)
1. **난독화의 세 방법을 하나의 변환으로 묶고 파일 전체에 건다.**
   - 문자열 배열: 글(`"…"`)뿐 아니라 이름 접근(`cfg.dumpState`의 `dumpState`)과 객체 열쇠(`{dumpState: true}`)도 배열로 옮겨 `[_0x…(0x6)]`로 바꾼다. 배열 돌리기: 시드로 고른 k칸 오른쪽으로 돌려 적고 실행할 때 `push(shift())`를 k번 해 되돌린다. 글자 코드: 배열 글을 글자마다 `\x7a`(0xff까지)·`\uXXXX`로 적는다.
   - 근거: 명세 F-B02 2·설계 2.7이 '문자열 배열·배열 돌리기·글자 코드'를 한 방법(`obfuscated`)의 재료로 적었다. 흔한 난독화 도구(javascript-obfuscator)의 문자열 배열·돌리기·유니코드 이스케이프 묶음과 같은 짜임이다(그 도구의 옵션 이름은 기억에 기댄 것 — 확인: 그 도구 README의 options 표. 새 라이브러리라 들이지 않았다, 설계 2.7).
   - 파일 전체에 거는 까닭(공정성): 정답 글만 배열로 옮기면 '배열에 있는 글 = 숨긴 것'이 겉모양 단서가 된다. 모든 글을 같은 함수로 풀게 하면 정답·미끼·평범한 화면 글이 모두 같은 겉모양이다. 이름 접근·열쇠까지 옮기는 것도 같은 까닭이다 — 글만 옮기면 `cfg.dumpState`처럼 설정 이름이 글 그대로 남아 플래그 정답만 숨기지 않은 꼴이 된다.
   - 변수·함수 이름은 바꾸지 않았다(`GEO_KEY`·`BUILD_TAG`가 보인다). 명세의 세 방법 밖이고, 이름은 정답·미끼 모두에 같은 정도의 뜻을 주어 한쪽 단서가 아니다.
   - '글자 코드'를 `String.fromCharCode(…)` 부름이 아니라 배열 글의 이스케이프로 본 까닭: 부름으로 하면 글마다 꼴이 달라 배열·돌리기와 따로 노는 둘째 숨김이 되고, 닻(번들에 있는 글)이 숫자 목록이 되어 결과 evidence에 들어가기 어렵다.
2. **소스맵은 난독화하지 않은 파일에만 붙였다.** 빌드는 맵의 `sourcesContent`에 변환 전 원본을 넣는다(`build.py` 머리글). 난독화 파일에 붙이면 숨긴 값이 맵에 글 그대로 나와 `obfuscated` 정답이 평문이 된다. hard-1은 난독화 주 번들 + 맵 있는 조각, hard-2는 맵 있는 시작점 + 난독화 화면 코드 + 라이브러리로 짜임을 다르게 했다(설계 2.7 '둘째 번들이 첫째의 되풀이가 되지 않게').
3. **`sourcemap_only`는 압축이 지우는 원본 주석에 둔다.** 이 압축은 `/*!` 밖 주석을 지우고 죽은 코드 지우기는 하지 않는다(`minify.py`). 그래서 '결과물에는 없고 맵에만'을 만드는 길은 주석뿐이다. 두 번들 모두 `sourcemap_only`가 있어야 해서(F-B02 3) 둘 다 원본이 든 맵이 있고, `complete: true`라 맵 노출(`source_map`, `none`)도 두 번들 모두 정답이다.

   - obfuscated: H1-D1 화면 바닥글에 늘 보이는 빌드 표식(비밀번호와 같은 base62 16자, 심기 계획으로 만듦), H2-D1 웹 푸시 VAPID 공개 키(공개하라고 만든 값, base64url 87자 — 시드 `hard-2/H2-D1`로 직접 만든 글을 원본에 적음)
   - split: H1-D2·H2-D2 설정의 공개 CDN 주소 + 경로 조각을 이은 사진 주소(버튼을 누를 때만 씀)
   - sourcemap_only: H1-D3·H2-D3 결과물 코드 어디에도 읽는 곳이 없는 개발 메모 주석(`verboseOcr`·`mockApi`). 같은 맵의 정답 주석(토큰·키·관리 경로)과 같은 겉모양이다
   - 미끼마다 '왜 문제가 아닌가'를 내용으로 적었고, 그 판단에 쓰는 단서(바닥글에 보임, 푸시 구독에 넘김, 읽는 코드 없음)는 번들 안에서 확인할 수 있다. 미끼 글에도 ㉰ 낱말·예약 이름이 없다(시험 둘이 번들 글과 풀어낸 배열 글 전체를 본다).
8. **값과 접두어.** 키 접두어 `drovik_`(hard-1), `nuvor_`·`oskel_`(hard-2). 허용 목록 안이고 앞 번들의 `zelto_`·`quvar_`·`mirtak_`·`fenzo_`·`lumac_`·`cablo_`·`trimba_`·`korvel_`과 겹치지 않는다(시험 `접두어_앞번들과_안겹침`). 토큰 둘의 서명 끝 글자는 표준 꼴(시험이 본다). 다시 만든 값은 없다.
9. **바깥 주소는 사용자 동작 뒤에만.** 공개 CDN 주소는 '원본 보기'·'사진 보기' 버튼 click 처리 안에서만 읽고(시험 `바깥주소는_누른뒤에만`이 찾기 번호로 자리를 본다), 웹 푸시 구독도 '배송 알림 받기' 버튼 뒤에만 한다. 페이지를 열 때 닿는 곳은 같은 출처의 `/api/…`와 사설 주소뿐이다.
10. **문법 검사는 `node --check`.** PATH의 node(22.19.0, 화면 빌드가 쓰는 것)로 실행하지 않고 읽기만 한다. node가 없으면 시험을 건너뛴다(그 PC에서는 결과물 바이트·지문 시험만 남는다). 시험이 헛돌지 않게 괄호 하나를 지운 결과가 실패하는지도 본다. 다른 안(파이썬으로 문법 검사기를 직접 씀)은 그 검사기 자체가 틀릴 수 있어 고르지 않았다. 이 시험은 번들을 실행하지 않으므로 '번들을 REA·Claude Code로 미리 돌려 보지 않는다'와 부딪히지 않는다.
11. **`minify.py`의 정규식 가르기 상수를 그대로 가져다 쓴다**(`_REGEX_AFTER_PUNCT` 등, 밑줄 이름). 같은 원본을 압축과 난독화가 다르게 토큰으로 나누면 한쪽만 깨진다. `minify.py`는 이 태스크의 고칠 파일 밖이라 공개 이름으로 바꾸지 않았다(문제와 개선에 적음).
12. 번들을 REA나 Claude Code로 미리 돌려 보지 않았다. 원본 `index.html`이 편집기 미리 보기에 떴으나 스크립트 경로가 자리(`{{asset:…}}`)라 JS가 실리지 않는다.

## 요청
- 설계: 계약 `answers.schema.json`의 미끼(`decoys`)에 `decoded_anchor` 칸이 없다. 난독화·인코딩 미끼를 풀어낸 값으로만 가리킨 결과는 '미끼 헛짚음'(F-G02 6㉯)으로 이름 붙지 않고 그냥 틀림이 된다. 정답은 풀어낸 값으로 맞히는데 미끼는 못 잡아, 풀어내는 쪽(가설상 조건 B)의 헛짚음이 R1 사례에서 덜 보일 수 있다. 미끼에도 선택 칸 `decoded_anchor`를 둘지 판단 바람(normal 미끼 N1-D1·N1-D2·N2-D2·N2-D3도 같은 처지)
- 설계: `minify.py`의 정규식 가르기 상수(`_REGEX_AFTER_PUNCT`·`_REGEX_AFTER_WORDS`·`_WORD`)를 `obfuscate.py`가 밑줄 이름 그대로 가져다 쓴다. 공개 이름으로 바꿀지(또는 두 모듈이 함께 쓰는 토큰 규칙을 한곳에 둘지) 판단 바람 — `minify.py`는 이 태스크의 고칠 파일 밖

## 사용자가 확인할 것
- 고른 것 1의 '파일 전체 난독화·이름은 그대로'와 고른 것 6의 '긴 값의 닻은 앞 16자의 글자 코드'가 어려움 난이도의 뜻에 맞는지(총괄 판단으로 충분하면 사용자 확인은 없어도 된다)

## 다음 세션이 알아야 할 것
- 난독화는 `plan.json`에 `"plugins": ["obfuscate"]`, `"steps": [{"step": "obfuscate", "files": ["<src 안 경로>"]}]`. 닻은 `{"value": "<ID>", "chain": "charcode:16"}`(심기 계획 값), 손으로 쓴 글은 `obfuscate.char_codes`로 만든 글자 코드를 `answers.in.json`에 글로 적는다(JSON에서 백슬래시 두 번).
- 난독화 원본이 받지 않는 꼴: 템플릿 글, 정적 `import … from`, 글 안 줄바꿈, 모르는 이스케이프(멈추고 원본 줄을 알린다). `{`·`,` 뒤 이름 + `:`를 열쇠로 보므로 블록 라벨·`=> { a: 1 }`을 쓰지 않는다. 줄 첫머리 `.then` 체인도 피한다.
- `obfuscate.py`가 생겨 easy·normal의 `build.json` `build_scripts_sha256`에는 `obfuscate.py`가 없다(번들 바이트·지문은 같다, 다시 빌드 시험 통과). T23 때 `encode.py`와 같은 처지다.
- `bench/targets.json`에는 hard 줄이 이미 있어 고치지 않았다(하위 작업 24.5 이름의 '대상 목록 줄').
