### 공정성 (조건 A·B 어느 쪽에도 치우치지 않는가)
- **같은 원자료 → 같은 바이트**: `score` 명령을 두 번 돌려 여섯 파일 sha256이 같다(시험). 실행 폴더를 읽는 차례·두 날짜 폴더로 나눔과 상관없이 표가 같다(시험). 좌표는 분수 → 소수 한 자리 글이라 float 끝자리가 바이트를 바꾸지 않는다.
- **조건 이름을 읽는 곳**: 지표·모으기·표·그림은 조건을 이름으로 가르지 않는다(`BASE_CONDITIONS`는 표에 늘 나올 줄 차례일 뿐). A↔B 이름을 바꾼 원자료로 `조건별` 표의 두 줄이 그대로 맞바뀐다(시험 `test_F_G05_조건이름을_바꾸면_칸만바뀜`). 사례(F-G06)만 명세대로 A·B를 부른다: 1·2는 대칭, 3(미끼 헛짚음)은 명세가 B만 — 사례 후보에는 B의 실수만 오른다. 숫자(미끼 헛짚음 수)는 `요약.md` 실행별 표에 두 조건 모두 있다.
- **대화 기록 줄(F-G06 4)이 B에 불리할 수 있던 곳**: REA(MCP) 결과는 JSON 글이라 evidence의 따옴표가 `\"`로 실린다. 글 그대로만 찾으면 B만 `-`가 많아진다. 그래서 JSON 한 겹·두 겹 꼴(ASCII 밖 그대로·`\uXXXX`)까지 찾는다(시험). 남은 추정: REA가 꾸민(beautify) 코드에서 옮긴 evidence는 빈칸이 달라 어느 꼴로도 안 나올 수 있다(B에 불리, 추정). 확인 방법: 첫 실험(24~36번) 채점 뒤 채점 레인이 `사례후보.md`의 대화 기록 줄 `-` 비율을 조건별로 센다 — 차이가 크면 빈칸을 지운 맞춤을 더할지 설계에 올린다.

- F-G06: 1·2는 그 대상에 두 조건 모두 채점한 실행이 있을 때만(위 공정성). 목록 한 줄 = 실행 하나의 결과 하나(5의 차례에 실행 ID가 있어서). 예시의 'B만 찾은 정답 1줄(짝이 된 B 실행 2개)'은 후보 1개로, 절 머리에 `후보 n개, 줄 m개`를 함께 적는다. 대화 기록 줄은 JSON 꼴까지 찾는다. 대화 기록 지문이 `run.json`과 다르거나 2MB를 넘거나 읽지 못하면 줄 `-`와 알림(요약.md).
- F-G05: '표식없으면_실패'를 '여는 표식만·끝 표식만·꼴이 틀린 표식(띄어쓰기·CRLF)'은 실패로 읽었다. 표식이 하나도 없으면 명세 예외대로 통과·0개. CR도 글자로 본다(줄 끝이 CRLF면 까닭에 그렇게 적음).
- 명령(F-R09 2)에 선택 인자를 더함: `--check <보고서>`(F-G05, 실패면 끝 코드 1), `--targets <대상 목록>`(기본 `bench/targets.json`, 내 앱 목록을 더할 때), `--tolerance <T>`(설계 2.5 '확인' 0·2·5로 다시 채점). `--results`는 여러 번 줄 수 있다(셋째 차례가 다른 날짜 폴더에 생길 때).
- `--out`에 쓰는 것: `표.md`(표마다 보고서 표식 꼴 — 문서 역할이 그대로 옮긴다), 그림 셋, `사례후보.md`, `요약.md`(셋째 권고, 다시 돌릴 실행, 읽지 못한 폴더, 대상별·실행별 숫자, Juice Shop 짝 없는 결과 — F-G03 출력 '실행별·조건×대상별'과 7의 목록).
- 칸 안 바깥 글(`md_cell`): `|`는 `\|`(F-G04 5), 그 밖에 `` \ ` * _ [ ] < > & ~ $ ``도 앞에 `\`, 줄바꿈은 `<br>`, 보이지 않는 글자(제어·서식·줄 구분)는 `\uXXXX` 글 — 보고서에 숨은 글자가 들어가지 않게(숨은글자 검사).

- 멈추는 꼴 전부:
  - 원자료 폴더 없음 → `ScoreError`, 실행 폴더 0개 → `ScoreError` — 명세 F-G05 예외('원자료 없음 → 실패') — `test_F_G05_원자료없음_실패`, 명령은 끝 코드 2 `test_F_G05_score명령_원자료없으면_멈춤`
  - 같은 (조건, 대상, 반복 차례)의 채점할 실행이 둘 이상 → `ScoreError` — 명세에 없음 — `test_F_G03_같은조건대상차례_실행둘이면_멈춤`
  - 대상 목록을 읽지 못함·계약 어긋남 → `ScoreError` / 두 대상 목록에 같은 ID → `ScoreError` / 정답지를 읽지 못함·계약 어긋남 → `ScoreError` — 명세에 없음 — `test_F_G05_대상목록·정답지를_읽지못하면_멈춤`
  - 정답지 경로가 저장소 밖 → `ScoreError` — 명세에 없음 — 시험 없음(계약 뜻 규칙 `bench/answers/<id>.json`이 먼저 막아 닿을 수 없는 두 번째 울타리)
  - 보고서를 읽지 못함 / 4MB 넘음 / UTF-8 아님 → `ScoreError` — 명세에 없음 — `test_F_G05_보고서파일을_읽지못하면_멈춤`(없음·UTF-8 아님, 크기는 시험 없음)
  - 사례 후보의 `findings.json`을 다시 읽지 못함 / 읽은 뒤 계약에 어긋남 → `ScoreError` — 명세에 없음 — `test_F_G06_findings를_다시읽지못하면_멈춤`
  - 결과 파일을 쓰지 못함 → `ScoreError` — 명세에 없음 — 시험 없음
  - 명령: `ScoreError` → 끝 코드 2, 보고서 검사 실패 → 끝 코드 1, 인자 틀림 → argparse 끝 코드 2 — 명세에 없음(F-G05 출력 '통과·실패') — `test_F_G05_score명령_보고서검사`, `…원자료없으면_멈춤`
  - (실패로 알림, 멈추지 않음) 보고서 표: 글자 다름·줄 수 다름(F-G05 3), 없는 이름(F-G05 4), 끝 표식 없음·여는 표식 없는 끝 표식·표식 꼴 틀림·CRLF(명세에 없음) — `test_F_G05_한글자다르면_실패`, `…줄이모자라거나_남으면_실패`, `…없는이름이면_실패`, `…표식없으면_실패`
  - (`-`와 알림, 멈추지 않음) 대화 기록 읽지 못함·2MB 넘음·sha256 다름 — 명세에 없음 — `test_F_G06_대화기록_지문이다르면_줄없이_알림`(읽지 못함·크기는 시험 없음)
  - T26 것(그대로): `read_runs`의 정답지를 받지 못한 대상 → `ScoreError`, `_choose_pairs`의 최대 짝 확인 → `AssertionError`

## 요청
- `bench/score/__init__.py`(T26 파일, 허용 범위 밖): 머리 문서에 새 모듈 다섯(`metrics`·`aggregate`·`tables`·`svg`·`recompute`·`cases`)과 `python -m score`를 한 줄씩 더하기 — 다음 채점 태스크에서.
- 설계: `bench/tests/score/__init__.py`가 없어 시험끼리 만들기 함수를 `from tests.score.test_f_g03 import`로 나눈다(`from test_f_g03`은 pytest는 되고 mypy가 못 찾음). 만들기 함수를 둘 자리(`tests/score/conftest.py` 또는 `__init__.py` + 도움 모듈)를 정해 주면 옮긴다.
- 설계(검사): 보고서(`docs/보고서/REA실험.md`)가 생기면 `check.py`에 F-G05 검사(`cd bench; uv run python -m score --results results/<날짜> --out <임시> --check ../docs/보고서/REA실험.md`)를 연결. 원자료 날짜 폴더를 고르는 법과, R2 `병렬효율.md`의 F-M02 표 이름을 이 검사가 알게 하는 길(F-M02 표 만들기를 `TABLE_NAMES`와 합칠지)이 필요.
- 문서: 위 '멈추는 꼴'의 '명세에 없음' 줄과 '명세가 정하지 않은 작은 것'을 F-G03~G06 예외·처리 규칙으로 옮길지.
- 문서(사용자 확인 전 값): F-G03 10 ㉯를 'N ≥ 3이면 범위와 상관없이 겹침을 본다'로 읽었다 — 명세 글에 맞는지.

## 문제와 개선
- 방법론: 배정문의 허용 범위에 `tests/score/__init__.py`·`conftest.py`가 없어 시험 만들기 함수를 시험 파일끼리 가져다 쓴다 — 첫 시도(`from test_f_g03`)는 pytest만 되고 mypy가 못 찾아 한 번 돌았다 → 새 시험 폴더를 여는 태스크의 허용 범위에 그 폴더의 `__init__.py`(또는 도움 모듈 하나)를 함께 넣는다.
- 방법론: testStrategy의 `test_F_G05_표식없으면_실패`가 명세 예외('표식이 하나도 없음 → 통과')와 글이 부딪혀 보였다 → testStrategy 이름에 무엇이 없을 때인지(여는·끝 표식) 한 낱말 더 적는다.
- 방법론: 백그라운드 명령을 `| tail`로 받으면 끝날 때까지 출력이 비어 진행을 볼 수 없었고, 기다리는 셸 되풀이도 180초에 백그라운드로 밀렸다 → 긴 검사는 처음부터 파일로 받고 끝 알림을 기다린다(레인 카드 '검사'에 한 줄).
- 프로젝트: 헤드리스 Edge 스크린샷은 창을 약 500px 아래로 줄이지 않아 '390px 확인'을 그대로 할 수 없다 → 확인할 화면 줄에 '좁은 상자(374px)에 넣어 찍기'를 적어 두거나 설계가 작은 스크린샷 스크립트를 둔다.
- 프로젝트: 옛 서버 시험 `test_F_S01_근거조각_키워드창_많아도_선형`(절대 5초 상한)이 이 PC에서 5.0~5.2초로 따로 돌려도 실패한다(backend 변경 없음) → 멈춘 옛 앱의 절대 시간 상한 시험은 상한을 비율(4배 입력에 8배 미만)로 바꾸거나 검사 '서버테스트'에서 시간 시험을 뺀다(설계).
- 프로젝트: Write 도구로 쓴 시험 소스의 `\u200b` 꼴이 실제 보이지 않는 글자로 들어가 숨은글자 검사에 걸렸다 → 보이지 않는 글자를 다루는 시험은 처음부터 `chr(0x200B)`로 만든다(코드규칙 시험 절에 한 줄).
