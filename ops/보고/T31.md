## 한 것
조건 B의 MCP 거르개 `bench/run/rea_mcp_filter.py`(표준 라이브러리만)를 만들었다. ## 명세와 달라진 점
명세가 정하지 않은 부분을 고른 것과, 명세보다 좁힌 것이다. 넓힌 것은 없다.
1. **F-R04 5④ 참조의 꼴**: 명세는 "첫 시험에서 REA 응답으로 정한다"였다. REA 6.10.1의 입력 계약 원본(`.tools/rea/node_modules/rea-agents/dist/domain/evidenceReference.js`의 `retainedEvidenceReferenceSchema` = 키가 정확히 `kind`·`evidence_id`, `kind: "retained-evidence"`, `evidence_id` = `ev_` + 소문자 sha256 64자)으로 정했다. 진짜 REA의 `tools/list`는 이 칸을 `{"type": "object"}`로만 알리므로, 거절 오류 글에 받는 꼴을 적었다(값은 싣지 않음). 실제 analyze 응답의 `evidence_id`가 이 꼴인지는 보정 실행에서 확인할 것(5절 출력 필드에 `evidence_id`가 있다).
2. **`native_observations`도 같은 세션 참조만**(명세는 `application`만): REA 계약에서 둘 다 같은 `evidenceInputSchema`(인라인 Evidence 또는 참조)라 인라인 Evidence로 경로를 실어 나르는 길이 같다. 게다가 REA는 `\Users\…`처럼 드라이브 없는 루트 기준 경로도 절대 경로로 받는데(`localPath.js`의 `windowsAbsolutePathPattern`), 그물 ⑤의 경로 꼴 목록에는 이 꼴이 없다. 조건 B에는 native 관찰을 만드는 도구가 없어 잃는 것이 없다.
3. **`mcp-B.json`에 `--target`·`--env-dir`를 더함**: 6절 명령 꼴에는 없지만, F-R04 입력에 'target 절대 경로'가 있고 규칙 1이 '실행 폴더 안 빈 폴더'를 요구한다. Claude Code가 MCP 서버를 어느 작업 폴더로 띄우는지 확인하지 않아(추정) 명령줄로 받는다. 둘 다(그리고 netguard 기록도) 푼 경로가 target 안이면 띄우지 않는다.
4. **경로 칸 ②에서 드라이브 없는 루트 기준 경로(`\x`·`/x`) 거절**: 명세의 허용 꼴(드라이브 절대·target 기준 상대·`\\?\C:\`)에 들지 않아 거절했다. 위 2의 이유로 REA가 이 꼴을 절대 경로로 받는다.
5. **그물 ⑤의 `..` 마디**: `..`뿐 아니라 끝에 점·공백이 붙은 `.. `·`...`도 경로 꼴로 본다(Windows가 마디 끝 점·공백을 지운다). 펼침 꼴에 `$(…)`도 넣었다. `%이름%`은 `%`와 `%` 사이에 한 글자 이상(`%[^%]+%`) — 이름에 공백이 들어갈 수 있어서다. 그래서 `%2F…%` 같은 URL 인코딩 글도 거절된다.
6. **㉢ 프록시**(`HTTP_PROXY`·`HTTPS_PROXY` = `http://127.0.0.1:9`)를 REA 환경에 넣었다: 규칙 1에는 없지만 REA환경.md 4절 셋째 겹이고 `rea_smoke.py`의 `safe_env`와 같다. 바깥 값은 `ENV_PASS`(rea_smoke와 같은 8개)와 `REA_MCP_TOOL_FAMILIES`만 넘긴다.

- 프로젝트: 명세가 'REA 응답으로 정한다'고 미룬 값(참조 꼴)이 REA 입력 계약 원본에 이미 있었다 → 설계 메모의 미결 값은 '어디서 확인하나(파일·명령)'를 같이 적으면 레인이 진짜 도구를 띄우지 않고도 닫을 수 있다
- 프로젝트: 3.10 #1의 예가 작업 폴더 기준으로 없는 경로라 꼴을 재지 못했다 → 공통 표의 예는 '어디서 본 상대 경로인지'와 '가리키는 파일이 있는지'를 같이 적으면 좋겠다
