## 반려 고침 1 (첫 검증, 보안 중간 2건)
- **[중간 1] S01-JWT 제곱 시간**: JWT를 `_SIMPLE`에서 빼 `_jwt_candidates`로 옮겼다. 시작 자리 `eyJ`는 `str.find`로 찾고, 한정자를 먹보로 바꾼 식(`{5,}+` 등)을 그 자리에서만 맞춘다. 단어 경계에서 시작해 실패하면 같은 덩어리(`[A-Za-z0-9_-]`) 안의 뒤쪽 `eyJ`도 첫 구간 끝이 같아 똑같이 실패하므로 덩어리 끝으로 건너뛴다. 경계가 아닌 자리(`aeyJ`)는 한 글자만 넘긴다(뒤쪽 `-eyJ`는 경계일 수 있음).
  - 재현 명령: 20KB 0.003초, 40KB 0.005초, 80KB 0.011초 (전 0.32/1.39/4.97초). 800KB 0.11초.
  - 명세 정규식과 같은 범위를 내는지 고정 씨앗 입력 3,000개(약 600개 걸림)로 대조하는 테스트가 있다. 경계가 아닌 자리도 덩어리째 건너뛰는 틀린 구현은 이 테스트가 잡는 것을 확인했다.
- **[중간 2] 개인키 후보 메모리·시간**: `_Candidate`에서 `raw`를 뺐다(범위·가린 값만). 원문은 `_collect`에서 받아들인 걸림에만 `content[start:end]`로 만든다. 후보를 전부 모아 정렬하지 않고 규칙 표 순서대로 규칙마다 흘려 보며 판정한다(각 규칙의 후보는 시작 순서로 나오므로 같은 규칙 안에서는 마지막으로 받은 것과만 겹칠 수 있다). 앞 규칙이 받은 범위는 규칙이 끝날 때 한 번 정렬해 합친다(`insort` 제거).
  - 재현 명령: BEGIN 1만 개(270KB) 최대 메모리 31KB(전 44MB). BEGIN 여러 개 + END 하나: 54KB 0.04초 → 216KB 0.16초(선형, 전 0.12 → 1.54초), 메모리는 입력의 약 2.3배(원문 = 블록 전체라 한 벌 복사는 필요).
- 테스트 이름 `test_F_S01_같은_원문은_규칙마다_따로`는 내용과 달라 `test_F_S01_같은_원문은_키이름이_달라도_하나로_묶는다`로 이름만 바꿨다(기대값 그대로). 낮음 '`_Candidate.raw`의 repr'은 필드가 없어져 사라졌다.

## 반려 고침 2 (재검증, 고칠 것 1~5)
1. **[보안 중간] `build_snippet` 제곱 시간**: 부를 때마다 만들던 `starts` 목록을 없애고 `bisect_*(spans, x, key=_span_start)`로 찾는다. 원문이 다른 AWS 키 5천·1만·2만 개 0.12·0.26·0.55초(전 0.54·1.96·24초), GENERIC 1만·2만·4만 개 0.27·0.52·1.02초(전 1만 개 3.4초). 테스트 `test_F_S01_원문이_다른_걸림_많아도_선형`(AWS 2만 개·GENERIC 1만 개, 각 3초 안, 발견 수도 단언).
2. **[빠짐] `DB_PASSWORD` 예시의 값 `****`**: `test_F_S01_GENERIC_DB_PASSWORD`에 단언을 더했다(명세 예시 그대로, 기존 기대값은 바꾸지 않음).
3. **[다름] GENERIC이 버린 값 안의 걸림을 놓침**: 값이 8자 미만이거나 닫는 따옴표가 없어 버리면 값 끝이 아니라 **키워드가 든 식별자 덩어리 끝**부터 다시 찾는다. 걸리면 명세 `finditer`처럼 닫는 따옴표 뒤부터 찾고, 자리표시값은 걸린 뒤에 버린다(명세 처리 규칙 3). 대조하다 하나 더 찾았다: 명세 정규식은 전체에 `(?i)`가 걸려 `[A-Za-z0-9_]`가 K(켈빈 기호)·ſ·İ·ı도 받는다. 식별자·꼬리 정규식에도 `re.IGNORECASE`를 걸어 맞췄다.
   - 검증 예시 `password:"pwd="abcdefghij"` → (15,25), `k:"x" password:"pwd:"abcdefghij"` → (21,31): 테스트 `test_F_S01_GENERIC_버린값_안의_키워드도_찾는다`.
   - 무작위 대조 `test_F_S01_GENERIC_명세_정규식과_같은_범위`: 고정 씨앗 입력 5,000개(약 1,100개 걸림, 하한 100 단언), 값 안에 다른 키워드·구분자·따옴표와 위 특수 글자를 섞었다.
4. **[다름] 표시 문자 U+E000/U+E001**: 표시 문자를 없앴다. 걸린 곳 앞(다른 걸림은 가린 값으로 바꾼 글)·걸린 곳·뒤를 따로 만들어 따로 ③을 하고 앞은 끝 40자, 뒤는 첫 40자를 잇는다. 표시 문자가 덩어리를 끊던 것과 결과가 같다(아래 '고른 것' (6)). 테스트 `test_F_S01_근거조각_대상글의_사설영역_글자는_그대로`(` zz  x="AKIA****LE" tail`), `test_F_S01_근거조각_긴덩어리는_걸린곳에서_끊긴다`(`abcd****AKIA****LE`, 지금 동작 지킴).
5. **[보고서]** '명세와 달라진 점'을 아래처럼 고쳤다. 명세 정규식과 '같은 뜻'이라는 말은 무작위 대조 테스트가 있는 JWT·GENERIC에만 쓴다.
- 재현 스크립트 `probe.py`: 세 입력 모두 명세와 구현 범위가 같고, 표시 문자 입력과 ③ 경계 입력은 위 기대값대로 나온다.
- '고치지 않을 것'(③ 경계 동작, 같은 규칙 안 겹침, 근거 조각 안 짧은 값, 보안 낮음 셋)은 건드리지 않았다.

## 명세와 달라진 점
명세 규칙 표·처리 규칙과 다르게 만든 것은 없다. 다만 명세가 정하지 않아 내가 고른 것이 있고, 결과가 명세 문장만으로는 정해지지 않는 것이 둘 있다((6)(7), 검증 '고치지 않을 것', 병합 뒤 CR 분석 대상).
- (1) 위치는 값(원문) 시작 위치(GENERIC도 값 위치, 키 이름 아님).
- (2) 자리표시값 `changeme`·`placeholder`는 정확히 일치할 때만, `your`·`example`·`process.env`는 접두 일치.
- (3) 근거 조각은 명세 순서대로 ②③(걸림 가리기, 긴 덩어리 가리기)을 한 뒤의 글에서 ④ 앞뒤 40자를 자르고 ⑤ 줄바꿈 치환(`\r\n` 하나 = 공백 하나)을 한다.
- (4) `.map`이 JSON 객체가 아니면 발견 없음(건너뜀 기록은 F-S02).
- (5) `.map`의 `sources` 이름이 없으면 `[] ` 접두, `sourcesContent`의 null·빈 문자열·글이 아닌 항목은 건너뜀.
- (6) 근거 조각 ③에서 긴 덩어리가 걸린 곳에 이어지면 걸린 곳 경계에서 끊어 따로 가린다(`abcdefghijklmnopqrstu-AKIA…` → `abcd****AKIA****LE`). 명세는 ③이 걸린 곳을 덮을 때 ④의 기준을 정하지 않았다.
- (7) 같은 규칙 안에서 값 범위가 겹치면 뒤쪽을 버린다. 그래서 END 없는 BEGIN의 4,096자 블록 안에 END 있는 다른 블록이 들면 개인키 하나로 센다. 명세 처리 규칙 2는 규칙 사이의 겹침만 말한다.
- 정규식: JWT와 GENERIC은 명세 정규식을 그대로 쓰지 않고 선형으로 다시 짰다. 둘 다 명세 정규식과 무작위 대조 테스트가 있다. URLCRED 값 묶음은 명세의 `+` 대신 먹보 `++`로 썼다(대조 테스트는 없다).
