# 배정문 양식 (총괄이 에이전트·세션에 주는 프롬프트)

짧게 쓴다. 내용은 파일 경로로 가리키고, 설명을 덧붙이지 않는다.
**모든 배정문의 둘째 줄은 `목적: <한 줄>`이다.** 태스크 머리줄이나 CR의 '목적'을 그대로 옮긴다. 다시 풀어 쓰지 않는다.
에이전트는 정의 파일(`.claude/agents/`)로 역할을 안다. 배정문에는 역할 설명을 다시 쓰지 않는다.

## 레인 (Agent, `subagent_type: lane-<레인>`, 백그라운드)
```
태스크: T<id> (task-master show <id>)
목적: <태스크 머리줄의 목적 그대로>
허용 범위: <고칠 파일 목록 그대로>
명세 기준: <커밋>
```

이어받기 (교대, 새 에이전트):
```
태스크: T<id> 이어받기. 인계서: ops/인계/T<id>-<MMDD>.md
목적: <그대로>
브랜치: task/<id>-<짧은이름> (git switch)
```

반려 (SendMessage, 같은 에이전트):
```
반려: T<id>. 사유와 재현 명령: ops/검증/T<id>.md. 같은 브랜치에서 고치고 다시 보고한다.
```

명세 바뀜 (SendMessage):
```
명세 바뀜: CR-<번호> (<ID>). 멈춤 — 지금 하위 작업을 마무리·커밋하고 '[T<id>] 멈춤(CR-<번호>)'으로 끝낸다.
명세 바뀜: CR-<번호> (<ID>). 계속 — 배정받은 그대로 끝낸다. 바뀐 부분은 수정 태스크로 온다.
```

## 검토 (Agent, 태스크마다 둘을 동시에)
```
security-reviewer: 범위 main..task/<id>-<짧은이름>. 발견만 심각도별로 몇 줄.
spec-checker: 태스크 T<id>, 명세 기준 <커밋>, 범위 main..task/<id>-<짧은이름>. 일치·빠짐·다름·명세에 없음 개수와 항목.
```

## 설계 (Agent, `subagent_type: design`)
```
할 일: <요청 처리: ops/보고/T<id>.md '요청' 칸 | CR-<번호> 기술 검토: docs/변경/CR-<번호>.md | 공통 태스크 T<id> | 설정 변경: …>
목적: <그대로>
사용자 승인: <있으면 무엇을 언제>
```

## 문서 (Agent, `subagent_type: spec-editor`)
```
할 일: <CR 분석: 원래 말 "<사용자 말>" / 목적 … (출처: …) | CR-<번호> 결정: <고른 안> → 반영 | 고침 모음: … | 결정기록: …>
목적: <그대로>
```

## 기록 (Agent, `subagent_type: doc-recorder`)
```
기록: 보고서 ops/보고/T<id>.md, … | 검토 ops/검증/T<id>.md, … | CR-<번호> | 설계 결정: <있으면>
```

## 세션 (사람과 길게 이야기할 때만 — 사용자가 있는 턴에 연다)
```
역할: 문서. ops/역할/문서.md를 읽고 따른다. 할 일: 명세 쓰기 | 큰 추가 CR-<번호> (사용자와 직접)
역할: 설계. ops/역할/설계.md를 읽고 따른다. 할 일: 단계 2 기반 | 구조 변경 …
목적: <그대로>
```
