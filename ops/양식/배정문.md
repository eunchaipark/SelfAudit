# 배정문 양식 (총괄이 세션에 보내는 첫 메시지·지시)

짧게 쓴다. 내용은 파일 경로로 가리키고, 설명을 덧붙이지 않는다.
**모든 배정문의 둘째 줄은 `목적: <한 줄>`이다.** 태스크 머리줄이나 CR의 '목적'을 그대로 옮긴다. 다시 풀어 쓰지 않는다.

## 레인

새 레인 (새 세션, 자기 worktree):
```
역할: 레인 (<레인>). 먼저 ops/역할/레인.md를 읽고 따른다.
목적: <태스크 머리줄의 목적 그대로>
태스크: T<id> (task-master show <id>)
허용 범위: <고칠 파일 목록 그대로> → .lane.json으로 만든다
브랜치: main에서 task/<id>-<짧은이름>
끝나면: ops/보고/T<id>.md, 마지막 메시지 첫 줄은 보고 첫 줄
```

같은 레인 세션에 다음 태스크:
```
다음 태스크: T<id>. .lane.json 허용 범위를 <목록>으로 바꾼다.
목적: <태스크 머리줄의 목적 그대로>
브랜치: main에서 task/<id>-<짧은이름>   (또는: T<앞> 브랜치에서 이어서)
```

이어받기 (교대):
```
역할: 레인 (<레인>). ops/역할/레인.md → ops/인계/T<id>-<MMDD>.md 순서로 읽고 이어서 한다.
브랜치: git switch task/<id>-<짧은이름>
```

반려:
```
반려: T<id>. 사유와 재현 명령: ops/검증/b<n>.md의 T<id> 절. 같은 브랜치에서 고치고 다시 보고한다.
```

명세 바뀜:
```
명세 바뀜: CR-<번호> (<ID>). 멈춤 — 지금 하위 작업을 마무리·커밋하고 '[T<id>] 멈춤(CR-<번호>)'으로 끝낸다.
명세 바뀜: CR-<번호> (<ID>). 계속 — 지금 태스크를 배정받은 그대로 끝낸다. 바뀐 부분은 수정 태스크로 온다.
```

## 검증
```
역할: 검증. ops/역할/검증.md를 읽고 따른다.
배치 <n>: task/<id>-…, task/<id>-… (이 순서로 합친다)
```

## 문서
```
역할: 문서. ops/역할/문서.md를 읽고 따른다.
할 일: (아래 중 하나)
  명세 쓰기 (단계 1)
  CR 분석: 원래 말 "<사용자 말 그대로>" / 목적: <총괄이 되물어 확인한 한 줄> (출처: 사용자 말 | ops/보고/T<id>.md '명세와 달라진 점' | ops/검증/b<n>.md)
  CR-<번호> 결정: <고른 안과 메모> → 반영
  고침 모음: <오타·표현 목록>
  기록: 보고서 ops/보고/T<id>.md, … | 검증 결과 ops/검증/b<n>.md | CR-<번호> | 설계 결정: <있으면>
```

## 설계
```
역할: 설계. ops/역할/설계.md를 읽고 따른다.
할 일: (아래 중 하나)
  명세 검토 (단계 1 끝)
  단계 2 기반
  CR-<번호> 기술 검토: docs/변경/CR-<번호>.md
  요청 처리: ops/보고/T<id>.md '요청' 칸
```

## 관제
```
역할: 관제. ops/역할/관제.md를 읽고 따른다.
할 일: (아래 중 하나)
  태스크 만들기: <명세 절 ID들>
  배치안 (레인 <n>)
  상태: T<id> <상태>
  CR 태스크 정리: CR-<번호>
  다시 계획: T<id> (CR-<번호>로 멈춤)
```
