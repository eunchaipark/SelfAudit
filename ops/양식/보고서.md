# 보고서 양식 — `ops/보고/T<id>.md`

**첫 줄**은 마지막 메시지의 첫 줄에도 그대로 쓴다. 총괄은 이 줄만 읽는다(앱 알림에는 보고의 앞부분만 보인다).

```
[T<id>] <완료|교대|막힘|반려 고침> | 검사 <통과|실패 n> | 문맥 약 <n>만 | 요청 <n>
```

## 한 것
1~3줄. 무엇을 어떻게.

## 바뀐 파일
주요한 것만. 커밋: `<첫 커밋>..<마지막 커밋>`

## 테스트
- 명령: `python ops/scripts/check.py`
- 결과: (check.py의 요약 줄 그대로)
- 예시 테스트: `test_<ID>_<상황>` … (기능 ID마다)

## 목적대로 됐나
- 목적: (배정문의 목적 줄 그대로)
- 됨 | 일부 | 안 됨 — 이유 한 줄. 명세대로 만들었는데 목적에 못 미친다고 보이면 그것도 여기에 적는다.

## 명세와 달라진 점
없으면 "없음". 있으면 ID와 무엇이 왜 다른지. (명세를 고칠지 코드를 되돌릴지는 변경 요청으로 사용자가 정한다)

## 요청
없으면 "없음". 허용 범위 밖 파일, 공통 파일, 새 폴더, 새 라이브러리, 마이그레이션, 미결 값.

## 사용자가 확인할 것
화면, 값, 결정이 필요한 것.

## 다음 세션이 알아야 할 것
같은 레인의 다음 태스크나 이어받는 세션을 위해. 없으면 "없음".

## 문제와 개선
`retro.py`가 이 줄들을 모아 `docs/회고.md`를 만든다. 형식을 지킨다: 첫 `→`에서 문제와 제안을 나누므로 문제 안에는 `→`를 쓰지 않는다. 없으면 "없음".
- 방법론: <일하는 방식에서 걸린 것 — 배정문·인계서·카드·훅·도구·토큰> → <고치면 좋을 것>
- 프로젝트: <명세·코드·외부 도구에서 걸린 것> → <고치면 좋을 것>
