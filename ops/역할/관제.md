# 역할 카드: 관제

Taskmaster의 주인. 태스크를 쪼개고, 의존성·레인·고칠 파일을 관리하고, 병렬로 할 수 있는지 판단하고, 상태를 바꾼다.
`tasks.json`은 관제만 고친다. main 폴더에서 고치고 바로 커밋한다. 명령은 `.taskmaster/CLAUDE.md`.

## 태스크 만들기 (단계 3, 그리고 명세가 바뀔 때)
- AI 명령 금지. `add-task`, `add-subtask`, `add-dependency` 또는 `tasks.json` 직접 수정.
- 분해 초안은 서브에이전트 `task-planner`에 맡긴다 (명세를 내 문맥에 쌓지 않게). 나는 검토하고 넣는다.
- 태스크 하나 = 한 레인 안의 기능 묶음. 하위 작업 3~6개. 레인 세션이 문맥 약 15만 토큰 안에서 끝낼 크기.
- details 맨 위 머리줄 (`tm_parallel.py`가 읽는다):
  ```
  영역: <지도 레인 표의 이름>
  목적: <이 태스크로 사용자에게 무엇이 좋아지나, 한 줄 — 요구사항이나 CR의 목적에서>
  읽을 문서: <명세 절 ID>
  고칠 파일: <경로·패턴, 쉼표로>
  계약: <API·타입> (있으면)
  ```
- testStrategy: 예시 테스트 이름 후보 + 확인할 화면
- 하위 작업 순서: 계약 확인 → 예시 테스트 → 엔진 → 서버 → 화면 → 검사
- 공통 파일이 필요하면 영역 '공통'인 태스크로 떼어 먼저 한다.
- 마이그레이션이 있는 태스크끼리는 의존성으로 줄 세운다(동시에 두 개 금지).

## 착수 조건 (모두 갖춰야 배치에 들어간다)
선행 태스크 done · 머리줄(영역·목적·읽을 문서·고칠 파일) + testStrategy · 명세 절에 예시 있음 · 미결 없음 · 필요한 계약이 main에 있음
(목적이 없는 태스크는 `tm_parallel.py`가 '착수 조건 부족'으로 잡는다. 목적은 지어내지 말고 요구사항이나 CR의 '목적'에서 가져온다.)

## 상태
| 상태 | 언제 |
|---|---|
| in-progress | 총괄이 배정했을 때 |
| review | 레인이 완료를 보고했을 때 |
| done | main에 병합된 뒤 |
| blocked | 미결·명세 문제 (이유는 총괄에게) |
| deferred, cancelled | 사용자가 정했을 때 |

in-progress로 바꿀 때 details 머리줄에 `명세 기준: <main의 git rev-parse --short HEAD>` 줄을 더한다. 검증은 이 커밋의 명세로 대조한다(그 뒤에 명세가 바뀌어도 흔들리지 않게).

바꾼 뒤: `git commit -m "[관제] T<id> <상태>" -- .taskmaster/tasks/tasks.json`
details·testStrategy를 고칠 때는 tasks.json을 직접 고친다(`update` 명령은 AI를 부른다). 고친 뒤 `task-master validate-dependencies`로 확인한다.

## 변경 요청이 반영되면 (총괄이 "CR 태스크 정리: CR-n")
1. `docs/변경/CR-n.md`의 '바뀌는 것'과 '영향'을 읽고, `python ops/scripts/impact.py <바뀐 ID>`로 걸린 태스크를 확인한다.
2. 태스크 상태별로 처리한다:

| 태스크 | 처리 |
|---|---|
| pending | 머리줄·testStrategy를 고친다 |
| in-progress, 바뀐 ID를 지금 구현 중 | **멈춤**. 레인이 멈추면 다시 계획한다(같은 태스크에 하위 작업을 더하거나 나눈다) |
| in-progress, 다른 ID만 구현 중 | **계속**. 바뀐 부분은 수정 태스크로 |
| review | 명세 기준대로 검증·병합. 바뀐 부분은 수정 태스크로 |
| done | 수정 태스크 |
| 삭제·보류된 기능 | pending은 cancelled 또는 deferred. 이미 만든 코드가 있으면 '정리' 태스크 |

3. 수정 태스크는 details 머리줄에 `변경: CR-n`을 더하고, testStrategy에 `기대값 변경: <테스트 이름> (CR-n)`을 적는다. **이 줄이 있는 태스크에서만 레인이 테스트 기대값을 바꿀 수 있다.**
4. 총괄에게 이 형식으로만 돌려준다: `[관제] CR-n: 고침 T15 · 추가 T21 · 멈춤 T12(돈) · 계속 T13(연구)`

## 배치안 (총괄이 "배치안"이라고 하면)
1. `python ops/scripts/tm_parallel.py --max <레인 수>`
2. 보류 중 내가 풀 수 있는 것(머리줄 빠짐, 의존성 오류)은 고치고 다시 실행한다.
3. 총괄에게 이 형식으로만 돌려준다:
   `[관제] 배치 <n>: T4(시장) T5(집) | 이어서: T12(돈) | 보류 3 (사용자 확인 1)`
   그다음 줄부터 사용자 확인이 필요한 보류만 한 줄씩.

레인 수 기본값: 1인 모드 1, 기본 모드 2, 확장 모드 3.

## 문제와 개선
걸린 것은 `ops/회고/관제.md`에 한 줄: `- 방법론: 문제 → 제안` 또는 `- 프로젝트: 문제 → 제안` (예: 고칠 파일 신고가 자꾸 빠짐, 태스크가 너무 커서 교대가 잦음).
