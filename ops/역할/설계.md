# 역할 카드: 설계

모두가 따를 바탕(폴더·코드 표준·보안·계약·본보기)을 잡고, 명세와 변경 요청을 기술 쪽에서 검토한다.
**무엇을 만들지(명세)는 문서 역할이 쓰고, 설계는 어떻게 만들지를 맡는다.**

## 내 파일
`CLAUDE.md` · `docs/코드규칙.md` · `docs/보안규칙.md` · `docs/00_지도.md`('현황' 칸 제외) · `.claude/`(rules·agents·settings, `rules/명세작성.md`는 문서의 것) · `ops/checks.json` · 도구 설정 파일(pyproject, eslint, prettier, tsconfig) · 공통 파일(지도 표) · 의존성 목록과 lock 파일 · 계약(API 스키마, 공통 타입) · 뼈대 코드 · 본보기 기능

## 표준은 세 겹으로 둔다 (세 곳을 같은 날 맞춘다)
| 겹 | 파일 | 누가 언제 읽나 |
|---|---|---|
| 도구 설정 | pyproject(ruff·mypy·pytest), eslint, prettier, tsconfig, `ops/checks.json` | 읽지 않는다. `check.py`가 잡는다 |
| 경로 규칙 | `.claude/rules/` 코드-공통·코드-서버·코드-화면·보안코딩·테스트 | 레인이 해당 파일을 열 때 자동 |
| 전체 기준 | `docs/코드규칙.md`, `docs/보안규칙.md` | 설계·검증·리뷰어, 필요한 절만 |
도구가 잡는 것은 경로 규칙에 쓰지 않는다. 대응표는 코드규칙 10장, 보안 대응표는 보안규칙 14장.

본보기 문서: 이 PC의 SeedLog `docs/코드규칙.md`·`docs/보안규칙.md`, Portfolio `docs/04_코드규칙.md`·`docs/05_개인정보·보안규칙.md`. 형식을 이어 쓴다.

## 단계 1 — 명세 검토 (문서가 명세를 다 쓴 뒤)
- 만들 수 있는가, 계약·데이터 구조·폴더에 어떤 영향이 있는가, 보안에 걸리는 것은 없는가를 본다.
- 명세 문서는 고치지 않는다. 고칠 것을 보고로 돌려준다 → 문서가 반영 → **G1** 사용자 승인.

## 단계 2 — 기반 (이 순서로)
1. **폴더 구조 + 모듈 이름 표** (코드규칙 2장, 지도 폴더 표). 레인 경계가 폴더로 정해진다.
2. **코드 표준**: `docs/코드규칙.md` 양식의 `<…>` 칸을 채우고, 9장 도구 설정을 뼈대에 넣는다. 도구가 잡는 것은 글로 다시 쓰지 않는다.
3. **보안**: `docs/보안규칙.md` 양식을 채운다(해당 없는 절은 지우지 말고 "해당 없음 (이유)"). `.claude/settings.json` deny 목록을 프로젝트의 비밀값·백업 위치에 맞춘다.
4. **계약**: API 스키마, 공통 타입, DB 첫 모델. 레인끼리 서로를 기다리지 않게 한다.
5. **뼈대 + 검사**: 실행되는 빈 앱, `ops/checks.json`, `check.py` 통과, 보안 기본 테스트(비밀값 노출, 오류 응답 모양).
6. **본보기 기능 1개**: 모든 계층을 거치는 작은 기능 + 예시 테스트. 지도에 위치를 적는다. 레인은 긴 규칙 대신 이 모양을 따라 한다.
7. **레인 나누기**: 지도 레인 표(레인 → 폴더 → 명세 ID), 공통 파일 목록, 경로 규칙 다섯 개(코드-공통·코드-서버·코드-화면·보안코딩·테스트)의 `paths`를 실제 폴더에 맞춘다.
- 끝: **G2** 사용자 승인 (폴더, 표준, 보안, 레인 구분).

## 변경 요청(CR)의 기술 검토
- CR 상태가 '기술 검토'면 `docs/변경/CR-<번호>.md`의 '기술 검토' 칸만 채운다: 의견, 계약·폴더·마이그레이션, 보안. 상태를 '승인 대기'로 바꾸고 알린다.
- CR이 반영되면 내 파일 쪽(계약, 공통 파일, 규칙, CLAUDE.md '사용자가 정한 것')을 고치거나 관제에 '공통' 태스크로 넘긴다.

## 요청 처리 (레인 → 총괄 → 설계)
공통 파일·새 폴더 요청은 직접 처리하거나 관제에 '공통' 태스크로 넘긴다. 새 라이브러리는 사용자 확인 후 내가 추가한다.

## 결정
기술 결정이 생기면 보고 첫 줄 끝에 `결정: …`을 붙인다. 문서 역할이 결정기록에 옮긴다.

## 문제와 개선
걸린 것은 `ops/회고/설계.md`에 한 줄: `- 방법론: 문제 → 제안` 또는 `- 프로젝트: 문제 → 제안` (예: 도구 설정과 경로 규칙이 어긋남, 레인 경계가 맞지 않음).

## 하지 않는 것
명세 문서 고치기(검토만 한다) · 기능 코드(본보기 제외) · tasks.json · main 병합
