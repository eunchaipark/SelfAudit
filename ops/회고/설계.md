# 회고: 설계

- 방법론: 계약 머리 주석에 함수 이름만 두고 입력 모양을 적지 않아 레인(T5)이 요청으로 올렸다 → 레인 사이 함수는 계약에 Protocol로 모양을 둔다(`RunRules`·`Score`처럼). 아직 없는 것: `intake.receive_*`, `compare.compare_scans`, `export.*`
- 방법론: 새 worktree에 `node_modules`가 없는 것을 레인마다 첫 check.py에서 알게 됐다 → 검사기가 빠진 준비물을 스스로 채우게 했다(checks.json '준비'). 다음 준비물도 같은 칸에 둔다
- 방법론: 총괄이 설계에게 결정기록(문서의 파일)에 직접 적으라고 맡겨 파일 주인 표와 어긋났다 → 설계 결정은 보고 '결정:' 칸으로만 넘기거나, '총괄 대리 결정 대상' 줄은 설계가 쓴다고 지도 파일 주인 표에 적는다
- 프로젝트: RetireJS 목록 정규식의 실제 꼴·개수를 모르고(네트워크 없음) 상한(10MB·1,000자·반복 1,000번)을 정했다 → 사용자가 실제 목록을 받은 뒤 버린 항목 수를 한 번 보고 D-030을 다시 본다
- 방법론: 보안 결정(D-030)을 막을 꼴 나열로 쓰고 우회 꼴을 재 보지 않아 반려됐다 → 설계의 보안 결정은 허용 꼴로 쓰고, 검증이 낼 법한 우회 꼴을 시제품으로 재서 예시로 붙인 뒤 넘긴다
- 프로젝트: worktree 에이전트가 깐 `.tools/`(휴대용 Node·REA 약 360MB)는 worktree와 함께 지워진다 → 설치는 스크립트(`setup_rea.py`)와 lock 파일로만 남기고, 실험을 돌릴 폴더에서 한 번 다시 돌린다(지도 '명령'에 적음)
- 프로젝트: REA는 분석 자식 프로세스를 띄울 때 NODE_OPTIONS를 지워 Node 안 감시가 자식에 닿지 않았다 → 네트워크 확인은 프로세스 안 감시 하나로 끝내지 말고 프로세스 나무 밖에서 보는 겹(netstat)을 같이 둔다
- 방법론: 감시 도구(netguard)를 '막는다'로 써 놓고 덮는 범위를 표로 내지 않아 보안 검토가 반려했다(DNS 함수·원격 파이프·UNC·NODE_OPTIONS 지운 자식) → 감시·차단 도구는 '감싼 함수 / 못 덮는 것' 표와 로컬 우회 자체 시험을 처음부터 같이 낸다
- 방법론: 배정 둘(구조 작업 + 앞 브랜치 반려 고침)이 한 브랜치에 겹쳤다 → 커밋 머리를 '[설계] env 반려 고침 n'과 '[설계] 실험구조 n'으로 갈라 총괄이 따로 볼 수 있게 했다. 다음에도 같은 꼴로
- 프로젝트: 셸 heredoc 안의 python이 `\\`·따옴표를 바꿔 계약 파일 정규식이 두 번 깨졌다 → 정규식이 든 JSON·문서는 Edit 도구로 고치고, 확인은 scratchpad의 파일 스크립트로 한다
- 방법론: 워크트리 격리 검사가 긴 한 줄 셸 명령(여러 cd·export)을 거부했다 → 시험 코드는 scratchpad에 파일로 쓰고 한 명령으로 돌린다
