# 회고 기록: 총괄

단계 0 준비 (2026-11-17, SessionKit을 만든 세션이 설치하며 적음. 세 가지 모두 키트에 반영함)

- 방법론: 다른 폴더에서 일하다 옮겨 온 세션에는 이 프로젝트의 훅과 .env 읽기 금지가 적용되지 않았다 → 역할 세션은 프로젝트 폴더에서 새로 연다 (적용하기 4-1)
- 방법론: 훅을 손으로 시험할 때 셸 명령 안에 직접 쓴 JSON의 역슬래시가 사라져 시험이 무효였다 → 훅 시험 입력은 python으로 만들고, 훅이 불렸는지는 .ops-logs/hooks.log로 본다
- 방법론: Taskmaster init 기본값에 AI 키 양식과 사용 통계 전송이 켜져 있었다 → 적용하기에 'Taskmaster 설정 정리' 단계를 둔다
- 방법론: 첫 커밋에서 줄바꿈(CRLF) 경고가 파일마다 한 줄씩 나와 세션 문맥을 채웠다 → 키트에 .gitattributes(LF 고정)를 넣는다
- 방법론: 총괄보다 높은 노력은 세션을 연 뒤에만 올릴 수 있어 문서 세션의 첫 턴(역할 카드 읽기·계획)이 중간으로 돌았다 → 모델표 적용 규칙 2에 '첫 턴은 낮은 노력으로 돈다'를 적고, 배정문 첫 턴은 읽기만 하고 멈추게 하거나 총괄을 그 노력으로 잠시 올려서 연다
- 방법론: 노력 바꾸기 호출이 자동 모드 훅과 겹쳐 한 번 거절되고 같은 입력으로 다시 보내야 했다 → 총괄 카드 '세션을 열 때'에 '거절되면 안내된 입력 그대로 한 번 다시'를 적는다
- 방법론: worktree로 여는 레인·설계 세션은 앱에서 저장소 '신뢰'가 먼저 필요해 밤 사이 자동 진행이 막혔다 → 적용하기 단계 0 '첫날 확인'에 'worktree 세션 하나 열어 저장소 신뢰'를 넣는다
- 방법론: 다른 세션의 보고로 깨어난 총괄 턴에서는 앱이 새 세션 시작을 막아(제안 카드만 됨) 사용자가 없는 밤에는 새 레인을 열 수 없었다 → 밤새 돌릴 레인 세션은 사용자가 있을 때 미리 열어 두거나(대기), 총괄의 서브에이전트로 레인 일을 하고 검증은 기존 검증 세션에 맡긴다
- 방법론: 마무리 보고와 CR 질문이 번호·용어만이라 사용자가 무엇을 정하는지 몰랐다(CR-002) → 총괄 역할 카드에 '사용자에게 보고하는 법'을 넣었다. spec-editor의 '사용자에게 물을 것'도 같은 형식으로 쓰게 정의를 고친다(design)
- 방법론: task-planner에 쓰기 도구가 없는데 배정문에서 파일을 쓰라고 했다(2026-11-20 밤) → 배정문 양식 '태스크 초안'은 "본문을 돌려주면 총괄이 ops/계획/에 저장"으로 적는다
- 방법론: 밤 레인 수를 '1'로 적어 둔 것은 5시간 84% 때 기준이었다. 리셋 뒤 1%라 기본 2로 돌렸다(총괄 판단) → 보드의 레인 수는 숫자가 아니라 '사용량 규칙대로'로 적는다
- 방법론: Bash heredoc·Write 도구 안의 `\u202E` 같은 표기가 실제 방향 문자로 바뀌어 문서·스크립트에 들어갔다(보드 10행, 보안규칙 67줄) → 보이지 않는 글자는 스크립트에서 `chr(0x202e)`로만 쓰고, check.py에 docs Cc·Cf 글자 검사를 넣는다(설계 요청)
- 방법론: 주간 사용량이 5시간보다 먼저 막는다(아침 한 창 70→80%: 설계 묶음·CR 둘·T6 구현·검토) → 보드 '밤 작업' 규칙에 주간 남은 폭으로 바퀴 수를 먼저 정하는 줄을 둔다
- 방법론: 레인 둘이 테스트를 도는 동안 main에서 check.py를 돌리면 시간 상한 테스트 두 개(test_F_C02_엔진_큰점검도_빠르다 2초, test_F_S01_근거조각_키워드창_많아도_선형 5초)가 부하로 실패한다(코드 변경 없는 문서 커밋인데 7초·2.3초) → 시간 테스트는 같은 입력의 작은 크기와 비율로 재거나(선형성), check.py에 '부하 중' 표시를 두고 총괄은 레인이 쉬는 때 main 검사를 다시 돈다
- 방법론: `check.py | grep '^검사' && git push`는 실패여도 grep이 성공해 push까지 갔다 → 총괄 명령은 check.py 종료 코드로 잇는다(`python ops/scripts/check.py >/dev/null && …`)
- 방법론: doc-recorder에 Bash가 없어 커밋·check_hidden을 못 하고 총괄이 대신했다(task-planner와 같은 꼴) → doc-recorder 정의에 Bash(git commit·check_hidden만)를 줄지 설계가 정한다
- 방법론: check.py 결과와 push를 `;`로 이어 실패해도 push했다(두 번째) → 총괄 명령 틀을 고정한다: `python ops/scripts/check.py >log 2>&1 && git push` 꼴만 쓰고, 멈춘 옛 앱의 시간 테스트는 부하 때 꺼지는 표시(예: 환경 변수로 건너뜀)를 설계에 요청
